# v4 — 정확도 개선과 FIFO 자원 절감

v4.0은 v3.3에서 FEx `inverse_t`를 16/6→16/5로 바꾼 기존 v3.4를 옮긴 기준선이다. 전체 16비트는 유지하며 소수부를 10→11비트로 늘렸고, Newton–Raphson 4회는 유지했다. v4.1에서는 출력 FC의 누산 정밀도를 높였고, v4.2에서는 FEx를 변경했다. v4.3부터는 FIFO와 양쪽 블록에서 파라미터를 전달할 때 드는 FF를 줄였다.

## 정확도

Python PA 평가에 동일 입력 7,680샘플과 상태 초기화 간격 2,560샘플을 사용했다. golden은 부동소수점 참조 모델이다.

| 지표 | Golden | v4.0 | v4.1 | v4.2 | v4.3~v4.6¹ |
|---|---:|---:|---:|---:|---:|
| NMSE (dB) | −45.52 | −44.96 | −45.03 | −45.19 | −45.19 |
| Golden 대비 NMSE 차이 (dB) | 0 | +0.56 | +0.49 | +0.33 | +0.33 |
| EVM (dB) | −49.42 | −48.75 | −48.78 | −48.90 | −48.90 |
| ACPR 좌 (dBc) | −53.59 | −53.61 | −53.51 | −53.43 | −53.43 |
| ACPR 우 (dBc) | −50.43 | −50.31 | −50.38 | −50.25 | −50.25 |

¹ v4.3~v4.6은 7,680샘플 RTL co-sim을 통과했고, 각 단계의 출력 비교에서 같은 벡터의 참조 또는 부모 출력과 일치해 v4.2의 PA 수치를 이어 썼다. v4.6은 호출마다 1층 가중치를 바꾸는 1,024샘플 추가 테스트도 통과했다. 검증 범위는 해당 벡터와 호출 조건이다.

## 블록별 FF 변화

v4.2에서 **FIFO 저장부와 제어부는 19,448 FF로 전체 41,015 FF의 47.4%**를 차지했다. 입력 준비 블록은 FIFO에 보낼 값을 준비하는 별도 계층이다. 소비·연산 블록에는 수신 파라미터 저장, 상태 및 파이프라인 FF도 포함된다. 표는 P&R 계층 보고서 기준이며, FIFO 제어부에는 공유 제어 계층의 FF도 포함한다. [계층별 집계 CSV](result/ff_breakdown.csv).

## 재현 자료와 확인 순서

현재 공유본은 버전에 따라 보관 범위가 다르다. 결과 보고서가 있다는 사실과 해당 폴더만으로 최종 RTL을 다시 생성할 수 있다는 사실은 구분한다.

| 대상 | 보관 자료 | 실행·검증 범위 |
|---|---|---|
| v2 최종, v3.1~v3.3, v4.0~v4.1 | 소스·테스트벤치·입력·참조 출력·재현 스크립트·보고서 | 각 README의 명령으로 C-sim·csynth·P&R을 새 경로에서 실행하도록 구성. 별도 재실행 여부는 각 문서의 검증 기록 참조 |
| v4.2 | [FEx 포함 소스](result/v4.2/fullrom_fc21/src/), PA 결과, P&R 보고서 | 구현과 결과를 확인할 수 있으나, 앞 버전과 같은 독립 실행 패키지는 제공하지 않음 |
| v4.3~v4.4 | [FIFO 제어 공유·깊이 축소 스크립트](result/v4.2/fifo_rtl/), 단계별 검증·P&R 보고서 | 특정 HLS 생성 RTL을 전제로 하는 후처리. 임의 버전의 RTL에 바로 적용하는 범용 설정이 아님 |
| v4.5~v4.6 | 단계별 co-sim·P&R 보고서, v4.6의 [75개 연결 변경 기록](result/v4.6/reports/rtl_changes.json) | 변경 결과의 근거를 확인하는 자료. 현재 공유 파일만으로 최종 후처리 RTL을 자동 재생성하는 전체 절차는 제공하지 않음 |

v4.3~v4.6을 재현할 때 필요한 순서는 다음과 같다.

1. v4.2 소스·테스트벤치·HLS 설정을 맞춰 기준 RTL을 생성하고 원래 실행본과 구조를 대조한다.
2. 제어 공유 → 깊이 축소 → 입력 준비 블록 출력 보관 제거 → 1층 가중치 직접 전달 순으로, 대상 단계까지 RTL 변경을 적용한다. 뒤 두 단계의 전체 후처리 절차는 별도로 확보해야 한다.
3. 변경한 RTL로 co-sim을 수행해 출력뿐 아니라 정지·재개 동작과 호출 간격을 확인한다. 직접 전달 단계는 가중치 변경 테스트도 확인한다.
4. 검증한 동일 RTL로 해당 버전의 합성 옵션을 적용해 P&R을 실행하고 자원·setup/hold 타이밍을 확인한다.

C++만 재합성하면 RTL 후처리 변경까지 자동으로 적용되지는 않는다. 보관 보고서는 당시 실행의 결과이며, 새 실행의 자원과 타이밍은 새 보고서로 판단한다.
