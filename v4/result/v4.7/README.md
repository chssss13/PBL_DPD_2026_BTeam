# v4.7 · GRU 2층 가중치 전달 경로 단축

v4.6을 부모로 채택한 변경이다. GRU 2층 가중치 150개를 처음 받아 둔 레지스터에서 연산 입력으로 연결해, 같은 값을 뒤로 전달하던 지연 단계를 우회했다. GRU 식과 가중치 정밀도는 그대로다. 목표 주기 15 ns를 만족하면서 전체 LUT가 1,591개 줄었다.

## 어떻게 이 후보를 찾았나

1. **사용자가 던진 질문.** 앞서 FIFO를 줄일 때 값을 보관하는 FF와 제어에 쓰이는 LUT가 함께 줄었다. 그렇다면 v4.6의 LUT도 용도를 나눠 보면 단순화할 수 있는 제어나 중복 저장이 남아 있지 않을까? 특히 한 소비 블록에 LUT가 약 97% 모였다는 집계만으로는 그 안에서 무엇을 줄일 수 있는지 알기 어려웠다. 사용자는 제어뿐 아니라 다른 가능성도 열어 두고, 배선 후 LUT를 용도별로 나눠 보자고 했다.
2. **분석에서 찾은 단서와 에이전트의 제안.** LUT는 계산뿐 아니라 여러 클럭 동안 값을 보관하는 시프트 레지스터(SRL)로도 쓰인다. v4.6에서 이 용도의 LUT는 3,039개였고, 실제 배치 위치를 가중치 경로와 대조하니 2층과 3층에 각각 1,275개가 대응했다. 에이전트는 가중치를 처음 받아 둔 곳에서 더 짧은 경로로 읽어도 곱셈 시점에 올바른 값이 도착하는지 시험하는 방법을 제안했다.
3. **사용자가 조정한 검증 범위.** 처음에는 2층 reset 게이트부터 확인하는 흐름이었다. 사용자는 reset을 확인하는 동안 다른 가중치도 함께 볼 수 있다고 제안했고, 이후에는 층·게이트 단위로 묶어 가능성을 판단하자고 했다. 이에 2층의 입력·순환 가중치 여섯 행렬(각 5×5)을 함께 바꿨다. 호출마다 가중치를 바꾸는 시험을 넣어 이전 호출 값을 잘못 읽는 경우도 확인했다.
4. **결과와 채택 판단.** 배선 후 지연용 LUT가 1,279개 줄었다. 전체 LUT 순감소 1,591개의 약 80%다. 처음의 제어 단순화 가설이 탐색의 출발점이었고, 이번 결과에서 직접 확인된 주된 절감 항목은 **가중치 전달을 늦추던 저장 회로**였다. 나머지 312개의 순감소 원인은 별도로 분리하지 않았다. 사용자는 면적 최적화를 유지하고, 이후 실제로 타이밍을 위반하면 옵션을 다시 비교하기로 했다.

## 출력 검증과 후속 후보

기존 가중치로 7,680샘플을 연속 120회 호출에 나눠 처리했다. 원본과 비교한 I/Q 출력값 15,360개, 출력 주소·클럭, 호출 완료 시점이 모두 일치했다. 별도로 가중치를 호출마다 바꾼 4회 연속 시험에서도 2층 변경본의 출력 기록이 원본과 일치했다. PA 지표는 이 벡터의 동일 출력에 근거해 v4.6 값을 이어 쓴다. 3층의 마지막 저장 단계까지 줄이는 실험은 v4.7을 부모로 하는 별도 후속 후보다.
