# 새 v2.5: hidden state 갱신식 재구성

최종 상태: 이 실험은 v3.1로 이관·완료한 뒤15ns 실패로 폐기했다.
최신 세부 설명과 실제 지표·실패 원인은 [v3.1 상세 문서](../../v3/docs/v3.1_hidden_state.md)를 참고한다.
아래는 실행 당시 계획 기록이다.

사용자 요청으로 이 후보는 [v3.1](../../v3/README.md)로 분류한다.
진행 중인 구현을 완료한 뒤 파일을 옮기며, 아래 v2.5 표기는 실행 당시 이름이다.

최종 보고 범위: 호출 오버헤드를 제외한 처리율, 정확도, II, 실제 구현 타이밍 및 자원.
현재 후보의 결과를 보고한 뒤 추가 후보는 실행하지 않는다.

새 v2 계열의 v2.5 실험이다. 과거 v2.5는 `repro_v2_5`에 보존된 별도 설계다.

기반은 검증된 새 v2.2다. 식만 바꾸며, 효과가 없었던 호출 제어 후보는 폐기했다.

기존: `h_next = (1-z)*n + z*h_prev`

후보: `h_next = n + z*(h_prev-n)`

data_t와 weight_t는16비트를 유지한다. 차분만 `ap_fixed<17,4,AP_RND,AP_SAT>`로
선언해 기존 소수부13비트를 보존한다. 16/3 두 값의 차는 [-8,8) 안이므로
17/4에서 손실 없이 표현한다. 차분을16/3에 먼저 대입하면 포화될 수 있어 피한다.
곱과 합을 중간에 data_t로 대입하지 않고 최종 h_next 대입에서만 기존 반올림/포화를 한다.
z는 sigmoid 출력 [0,1]이고 기존1-z도 같은 소수 격자에서 정확히 표현된다.
이 조건에서는 두 식의 최종 반올림 전 정수 분자가 같다.

Python에서 기존 식과 변형 식의 전체7680샘플을 비교한다. C/RTL 역시 기존 식 참조에
비교하므로 참조만 함께 바꿔 차이를 숨기지 않는다.
식상 곱셈 수 감소가 실제 DSP나 타이밍 개선으로 이어지는지는 보고서로 확인한다.
차분→곱셈의 직렬 의존으로 지연이 늘어날 가능성도 있어 성능 향상을 단정하지 않는다.

새 v2.5를 실행한다. 무거운 구현은 병렬 실행하지 않는다.
C 전체 비교/PA → II≤2 → RTL 전체 비교/PA/호출 간격 → 15ns 구현 순서다.
이 후보는 식의 효과를 측정하려고 호출 처리율이 미달해도 타이밍/자원까지 기록한다.
호출 오버헤드 포함33.3MSps 합격 여부는 별도로 유지한다.

기록: `results/hidden_flow.log`, `results/v2.5/state.json` 및 단계별 로그.
