# v2.3: start propagation 제거 — 폐기

2026-11-04. v2.2를 기반으로 top ResGRU의 DATAFLOW 지시문 하나만 변경했다.

## 목적과 변경

```cpp
// v2.2
#pragma HLS DATAFLOW
// v2.3
#pragma HLS DATAFLOW disable_start_propagation
```

내부 process로 전달되는 시작 토큰의 동기화가 호출 간격을 늘리는지 확인하려는 실험이다.
BRAM ROM·MAC 트리·hidden state 기존 식은 유지했다. 64샘플 호출과 reset 의미도 유지했다.
Vitis HLS/Vivado2024.1, xczu7ev-ffvc1156-2-e,15ns, uncertainty1ns,
DSP full register=false, 실제 LOOP_T 목표II2 조건이다.
data16/3, weight16/4, accum32/12, AP_RND/AP_SAT로 기존 후보와 같다.

## 결과

| 지표 | v2.2 | v2.3 |
|---|---:|---:|
| 전체 C/Python·C/RTL·RTL/Python | PASS | PASS |
| 비교 입력 | 7,680샘플 | 7,680샘플 |
| PA NMSE dB | −43.67 | −43.67 |
| ACPR L/R dBc | −51.82/−48.38 | −51.82/−48.38 |
| LOOP_T II | 2 | 2 |
| RTL 호출 지연 cycle | 167 | 167 |
| 실제 호출 간격 cycle | 134 | 134 |
| HLS 추정 주기 ns | 13.789 | 13.789 |
| HLS 추정 LUT / FF | 146,256 / 142,396 | 동일 |
| HLS 추정 DSP / BRAM_18K | 711 / 100 | 동일 |
| 실제 구현 타이밍·자원 | 측정 완료 | 미측정 |

당시 호출 오버헤드 개선 여부를 확인했지만 어느 관측 지표도 개선되지 않았다.
RTL 호출 간격으로 계산한31.8408MSps도 같아서 배치배선을 생략했다.
이 처리율은 이전 실험의 기록일 뿐 현재 합격 조건은 아니다. 현재 목표는 호출 오버헤드를 제외한다.

## 판정과 보존 범위

사용자 요청으로 폐기했다. 재실행을 비활성화했고 개별 프로젝트·결과 폴더는 현재 없다.
이 문서는 삭제 전에 확인한 [호출 제어 실험 요약](CALL_OVERHEAD.md)을 바탕으로 남긴 기록이다.
원시 보고서가 남아 있는 v2.1/v2.2와 근거의 보존 수준이 다르다.
실제 배치배선이 같을 것이라고 추정하거나15ns PASS라고 표시하지 않는다.
제어 지시문 변경만으로 이 설계의 병목을 제거하지 못했다는 범위에서 해석한다.
