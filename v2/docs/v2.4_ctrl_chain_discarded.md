# v2.4: ap_ctrl_chain 호출 제어 — 폐기

2026-11-04. v2.3을 이어서 바꾼 후보가 아니라 v2.2에서 독립적으로 시작했다.

## 목적과 변경

top ResGRU에 아래 인터페이스를 추가했다. DATAFLOW는 v2.2의 기본 설정을 유지했다.

```cpp
#pragma HLS INTERFACE ap_ctrl_chain port=return
#pragma HLS DATAFLOW
```

호출 제어가 다음 호출의 시작을 막는지 확인하고 중첩으로 호출 간격을 줄이려는 실험이다.
연산식·BRAM ROM·MAC 트리·가중치·블록64·reset 간격2560은 유지했다.
Vitis HLS/Vivado2024.1, xczu7ev-ffvc1156-2-e, 클록15ns, uncertainty1ns,
DSP full register=false, data16/3·weight16/4·accum32/12, AP_RND/AP_SAT 조건이다.

| 실제 구현 타이밍·자원 | 측정 완료 | 미측정 |

이 테스트벤치와 입력 패턴에서는 관측 지표가 바뀌지 않았다. 호출 오버헤드 포함 처리율도
31.8408MSps로 같아 당시 후속 배치배선을 생략했다. 현재는 호출 오버헤드를 평가에서 제외한다.
ap_ctrl_chain 자체가 모든 설계에서 무효라는 결론은 내리지 않는다.

## 판정과 보존 범위

사용자 요청으로 폐기했다. 재실행은 비활성화했고 개별 프로젝트·결과 폴더는 현재 없다.
남아 있는 근거는 삭제 전 확인한 [호출 제어 실험 요약](CALL_OVERHEAD.md)이다.
실제 구현 타이밍·자원은 미측정이며 미측정을 PASS로 해석하지 않는다.
별도 소프트웨어 enqueue나 시스템 전송 속도 개선을 측정한 실험도 아니다.
