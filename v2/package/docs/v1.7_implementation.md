# v1.7: v1.6 Vivado 배치·배선 결과

2026-10-16. v1.6의 기존 prj_e08/sol1을 초기화하지 않고
`export_design -flow impl -format ip_catalog` 실행. Vivado 2024.1,
xczu7ev-ffvc1156-2-e, 목표 15 ns. 정상 실행 약 52분 58초.

## 결과

배치·배선 완료, unrouted nets=0. HLS export 종료 코드는 0이지만 타이밍은 실패.

동일 FPGA와 목표 클록에서 수행한 v0 구현 결과와 비교한다. 두 열 모두 Vivado 구현 보고서 값이며 HLS 자원 추정치가 아니다.

| 항목 | v0 impl | v1.7 impl | v0 대비 변화 |
|---|---:|---:|---:|
| 목표 클록 주기 | 15.000 ns | 15.000 ns | 동일 |
| LUT | 46,646 | 66,859 | +43.33% |
| FF | 49,546 | 49,754 | +0.42% |
| DSP | 648 | 711 | +9.72% |
| BRAM / URAM | 0 / 0 | 0 / 0 | 동일 |
| SRL (LUT와 별도 합산하지 않음) | 5,344 | 5,703 | +6.72% |
| Post-Synthesis period | 14.346 ns | 19.266 ns | +34.30% |
| Post-Route period | 17.129 ns | 24.054 ns | +40.43% |
| 15 ns 타이밍 판정 | 실패 | 실패 | — |
| WNS | -2.129 ns | -9.054 ns | -6.925 ns |
| WHS | +0.021 ns | +0.019 ns | -0.002 ns |

변화율은 `(v1.7 − v0) / v0 × 100`이다. WNS/WHS는 부호가 있는 여유 시간이므로 변화량(ns)으로 비교한다. WNS 음수는 setup 타이밍 위반, WHS 양수는 hold 여유를 의미한다.

v0 대비 LUT는 20,213개(약 43.3%), DSP는 63개(약 9.7%) 증가했고, Post-Route 주기는 6.925 ns(약 40.4%) 길어졌다. v0 역시 배치·배선 후에는 15 ns를 만족하지 못했다. WNS/WHS는 각 버전의 실제 routed timing 보고서에서 확인했다.

v0 근거: [export_impl.rpt](../results/E00_v0_implementation/export_impl.rpt).
v1.7 근거: [export_impl.rpt](../results/v1.7_implementation/report/export_impl.rpt).
WNS/WHS 근거: [v0 timing](../results/E00_v0_implementation/ResGRU_timing_routed.rpt), [v1.7 timing](../results/v1.7_implementation/report/ResGRU_timing_routed.rpt).
v1.7은 정확도 복원과 합성 스케줄 변경을 포함하므로 자원·지연 차이를 활성화 LUT 하나의 영향으로 해석하지 않는다.

HLS II=2 및 전체 RTL 정확도 PASS는 v1.6에서 확인했으나, 15 ns에서의 물리 타이밍은 미달.
보고 주기 24.054 ns로 단순 환산한 주파수는 약 41.57 MHz,
II=2 기준 정상상태 처리율은 약 20.79 MSps. 보드 실측 수치가 아니며 블록 제어 오버헤드는 제외.
33.3 MSps 목표를 만족한 최종 설계로 판단하면 안 됨.

HLS LUT 추정 243,879개(105%)와 달리 구현 후 자원은 칩에 수용되었다.
함수 표가 제거된 것이 아니라 구현 계층 보고서에 sigmoid/tanh 회로별 LUT 사용량이 남아 있음.

## 결과 보관과 재현

results/v1.7_implementation/report/export_impl.rpt 및 ResGRU*.rpt에 최종 자원·타이밍·계층 보고서 보관.
impl_retry.log는 정상 구현의 전체 로그. 최초 제한 환경 실행은 cscript 권한 오류로 중단했고,
정상 권한에서 재시도해 위 결과를 얻었다.

재현: Vitis HLS 2024.1 Command Prompt, v1 폴더에서
`vitis_hls -f scripts/impl_existing.tcl` (기존 v1.6 합성 프로젝트 필요).
프로젝트가 없으면 먼저 scripts/run_ii2_candidate.cmd로 생성한다.

다음 작업은 최악 타이밍 경로를 분석하고, 정확도와 II=2를 유지하면서
조합 경로 지연/배선 지연을 줄이는 것. 이번에는 새 최적화나 재구현까지 수행하지 않음.
