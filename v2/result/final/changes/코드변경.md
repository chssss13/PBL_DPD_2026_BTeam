# 코드 변경 부분 모음

[변경 요약으로 돌아가기](../docs/v1_v2_변경요약.md)

각 단계의 **어느 파일·어느 함수에서 무엇을 바꿨는지**만 모았다. 1~8번은 v0에서 v1을 만든 과정이고, 9~15번은 그 v1을 기반으로 진행한 후속 변경이다. 코드는 변경 부분의 발췌·요약이며, 실행할 전체 소스는 [src](../src/)에 있다. 과거 버전 전체 소스는 필요하지 않다.

단계별 설명의 이전 형식은 당시 값을 뜻한다. 최종 소스에는 후속 변경까지 누적되어 있다. diff는 비교용 자료이며 최종 소스에 다시 적용할 파일이 아니다.

<a id="change-01"></a>

### 1. 은닉 상태 리셋 주기 — v0 대비

**위치:** `ResGRU`의 `GRU_single` 호출, 함수 인터페이스, 테스트벤치의 구간 시작 신호.

매 호출의 `t==0`에서 초기화하던 것을 `segment_start && (t==0)`으로 바꿨다. 블록 크기 `TIME_STEP=64`는 유지하며, 테스트벤치가 2,560샘플 구간의 첫 블록에서만 `segment_start`를 보낸다.

**파일·함수 위치:** multi_gru.cpp / multi_gru.h / tb_resgru.cpp — `ResGRU → GRU_single 호출, segment_start 인자, TB 블록 루프`.

최종 코드: [multi_gru.cpp](../src/multi_gru.cpp) · [multi_gru.h](../src/multi_gru.h) · [tb_resgru.cpp](../tb/tb_resgru.cpp)

### 2. 기본 자료형 범위 — v0 대비

**위치:** `config.h`의 `data_t`, `weight_t` typedef. data/weight를 각각 `ap_fixed<16,2,...>`에서 `ap_fixed<16,3,...>`으로 변경한 단계다. 이후 5번에서 weight만 다시 변경했다.

**파일·함수 위치:** config.h — `data_t / weight_t typedef`.

최종 코드: [config.h](../src/config.h)

<a id="change-03"></a>

### 3. 활성화 함수 — v0 대비

**위치:** `Gate_Calc_PE`의 r/z sigmoid와 n tanh 호출, `activations.h`의 활성화 계산.

hard 근사를 sigmoid/tanh의 **4,096칸 직접 조회**로 바꾸고 인덱스에 반올림을 적용했다. 이 단계의 sigmoid 범위는 −8~8, tanh는 −4~4다. 8번에서 이 함숫값을 조합 조회로 구현했고, v2의 9번에서 보간으로 대체했다.

**파일·함수 위치:** gru_cell.h / activations.h — `Gate_Calc_PE의 활성화 호출과 sigmoid/tanh 구현`.

최종 코드: [gru_cell.h](../src/gru_cell.h) · [activations.h](../src/activations.h)

<a id="change-04"></a>

### 4. FEx 역제곱근 형식 — v0 대비

**위치:** `linear_layer.h::FExLayer`의 `inverse_t`.

처음에는 `data_t`로 저장하던 `inv_sqrt`를 전용 `ap_fixed<16,8,AP_RND,AP_SAT>`로 바꿔 표현 범위를 넓혔다. 이후 `ap_fixed<16,6,AP_RND,AP_SAT>`로 조정해 소수부 정밀도를 늘렸다. Newton–Raphson 반복은 4회다.

**파일·함수 위치:** linear_layer.h — `FExLayer의 inverse_t / inv_sqrt`.

최종 코드: [linear_layer.h](../src/linear_layer.h)

### 5. 가중치 표현 범위 — 2번 이후 대비

<a id="change-06"></a>

### 6. HLS 스케줄 설정 — 정확도 복구 후보 대비

**위치:** 합성 Tcl. C++ 계산식 변경이 아닌 스케줄 설정 변경이다. 클록은15ns, uncertainty는4.05→1ns로 조정하고 아래 세 설정을 적용했다.

```tcl
set_clock_uncertainty 1.0
config_schedule -enable_dsp_full_reg=false
set_directive_pipeline -II 2 "ResGRU/LOOP_T"
```

**파일·함수 위치:** scripts/reproduce.tcl — `clock / schedule / LOOP_T directive`.

최종 코드: [scripts/reproduce.tcl](../scripts/reproduce.tcl)

<a id="change-07"></a>

### 7. 상태 갱신식 — 6번 이후 대비

**위치:** `gru_cell.h::Gate_Calc_PE`의 `h_next[i]` 계산.

```cpp
// 이전 식의 요약
h_next[i] = (1-z)*n + z*h_prev[i];
// 변경 후
h_next[i] = n + z*(h_prev[i]-n);
```

**파일·함수 위치:** gru_cell.h — `Gate_Calc_PE의 h_next 계산`.

최종 코드: [gru_cell.h](../src/gru_cell.h)

<a id="change-08"></a>

### 8. LUT 조회 구조 — 7번 이후 대비, v1 완성

**위치:** `activations.h::sigmoid_comb/tanh_comb`, `activation_comb_tables.h`, GRU의 호출부.

BRAM에 저장한 표를 읽던 방식에서, 같은 함숫값을 전체 분할된 조합회로로 조회하고 `LATENCY min=0 max=0`을 요청하도록 변경했다. **3번은 근사값·조회 방식의 선택, 8번은 그 표를 하드웨어에서 읽는 구조 변경**이다.

**파일·함수 위치:** activations.h / activation_comb_tables.h — `sigmoid_comb / tanh_comb의 표 조회`.

최종 코드: [activations.h](../src/activations.h) · [activation_comb_tables.h](../src/activation_comb_tables.h)

<a id="change-09"></a>

### 9. 보간과 비트 축소 — 원본 v1 대비, v2 작업 시작

**위치:** `config.h`, `activations.h::sigmoid_comb/tanh_comb`, 새 `activation_interp.h`.

- data16,3→15,3, weight16,4→14,4. accum18,3 유지.
- 직접 조회→양 함수 모두 `[-4,4)`의 256구간 보간.
- 구간의 시작값 B와 차이 D를 읽고 `B + ((D*fraction+64)>>7)` 계산.

**파일·함수 위치:** config.h / activations.h / activation_interp.h — `자료형, sigmoid_comb / tanh_comb, 보간 표`.

최종 코드: [config.h](../src/config.h) · [activations.h](../src/activations.h) · [activation_interp.h](../src/activation_interp.h)

### 11. GRU 누산 폭 확대 — v2.4-S 대비

**위치:** `gru_cell.h::Recurrent_Gate_MAC`, 새 `Experiment_Input_MAC/MVM`, `GRU_Kernel_PE` 입력 MVM 호출.


**파일·함수 위치:** gru_cell.h — `Recurrent_Gate_MAC / Experiment_Input_MAC / GRU_Kernel_PE`.

### 14. 상태 갱신용 z 표현 — 13번 대비

**위치:** `gru_cell.h::Gate_Calc_PE`에서 sigmoid로 z를 얻은 뒤 상태식을 계산하는 부분.

```cpp
ap_ufixed<12,0> z_gate;
z_gate.range(11,0) = z.range(11,0);
h_next[i] = n + z_gate*(h_prev[i]-n);
```

기존 상태식의 `z`를 `z_gate`로 교체했다. sigmoid 출력 자체의15,3 형식과 표는 유지하며, 상태 곱셈에 넣는 값만 unsigned12,0으로 표현한다.

**파일·함수 위치:** gru_cell.h — `Gate_Calc_PE의 z_gate`.

최종 코드: [gru_cell.h](../src/gru_cell.h) · [이전 채택 단계 대비 diff](diffs/14_gru_cell.diff)

### 15. 상태 결과의 최종 포화 생략 — 14번 대비, 현재 최종

**위치:** 같은 `Gate_Calc_PE`의 상태식 저장 부분. 바로 위 14번의 `h_next` 대입을 다음으로 바꿨다.

```cpp
typedef ap_fixed<data_T::width, data_T::iwidth, AP_RND, AP_WRAP> state_round_t;
state_round_t h_rounded = n + z_gate*(h_prev[i]-n);
h_next[i].range(data_T::width-1,0) = h_rounded.range(data_T::width-1,0);
```

출력 폭과 반올림은 유지하고 상태 결과의 최종 포화 선택만 생략했다. GRU 곱의18,3 변환과 wide 누산의 마지막18,3 변환은 유지한다.

**파일·함수 위치:** gru_cell.h — `Gate_Calc_PE의 state_round_t / h_rounded / h_next`.

최종 코드: [gru_cell.h](../src/gru_cell.h) · [이전 채택 단계 대비 diff](diffs/15_gru_cell.diff)
