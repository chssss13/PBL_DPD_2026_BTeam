# v1.5: 현재 정확도 후보 HLS 합성

2026-10-16, Vitis HLS 2024.1 Windows. v1.4의 기본 후보:
data_t 16,3 / weight_t 16,4 / accum_t 32,12,
FEX_INTERNAL_FIXED=1, FEX_INV_I=8, reset 입력 사용.

## 결과

csynth_design 종료 코드 0, Verilog/VHDL 생성 완료. 소요 약 4분 55초.
double exp/tanh/sqrt/역수 사용이 이번 코드의 HLS 합성을 막지는 않았다.
RTL co-sim 및 Vivado 합성/배치배선은 실행하지 않았으므로 RTL 정확도와 보드 수용/타이밍은 미확인.

| 항목 | HLS 합성 결과 |
|---|---:|
| LOOP_T II | 72 |
| LOOP_T iteration latency | 268 cycles |
| 최상위 64샘플 latency | 4809 cycles / 72.135 us (15 ns 기준) |
| 최상위 호출 interval | 4608 cycles |
| Estimated clock | 10.895 ns |
| LUT 추정 | 237835 (103%) |
| FF 추정 | 179777 |
| DSP 추정 | 647 |
| BRAM_18K 추정 | 25 |

목표 II=2는 실패. 동일 클록에서 정상상태 처리율은 v0 II=2 대비 1/36.
15 ns 목표 클록을 가정한 처리율은 약 0.926 MSps이며, 실제 구현에서 확인한 처리율은 아님.
HLS 추정 LUT 103%는 구현 자원 초과 확정 판정이 아니며, v0 구현 후 자원과 직접 비교하지 않는다.

## 병목 근거

로그에 은닉 상태 write/read 간 carried dependence II violation이 기록됨.
Loop_LOOP_T_proc 보고서에서 sigmoid instance latency 28 cycles,
tanh instance latency 40 cycles. reset gate r -> candidate tanh -> next hidden의
직렬 의존성을 가진 경로에 긴 수학 함수가 위치함.
각 함수 자체의 II=1이 GRU 전체 II=1 또는 II=2를 보장하지 않음.

현재 후보는 PA 정확도 기준은 통과했지만 처리율을 포함한 완성 v1이 아니다.
다음 후보는 정확도 여유를 지키면서 활성화 함수를 LUT/구간별 고정소수점 계산으로 대체하고
FEx의 부동소수점 계산도 비용을 확인하며 대체해야 한다.
