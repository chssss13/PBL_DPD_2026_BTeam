# v0 알려진 문제 — 논문 HLS 설계를 학습 가중치로 돌렸을 때

**학생 배포용** · 2026-10-12

## 배경

v0은 연구실 LW-ResGRU 논문의 HLS 설계 원본입니다 (H=5, L=3, Vitis HLS 2024.1, xczu7ev). 논문은 이 설계로 **자원 사용량과 처리율(II=2)** 을 보고했습니다. 그러나 이 설계는 **더미 가중치로만** 합성·시뮬레이션되었고, 학습된 가중치로 출력 정확도를 확인한 적은 없습니다.

조교가 학습 가중치(seed 4574)와 v0의 연산 방식을 Python 참조 모델로 재현해 측정한 결과, v0을 그대로 쓰면 정확도가 다음과 같이 떨어질 것으로 예상됩니다.

| | NMSE | ACPR L / R |
|---|---|---|
| 학습 모델 (float) | −45.52 dB | −53.59 / −50.43 dBc |
| **v0 동작 (예상)** | **−26.67 dB** | **−39.48 / −36.09 dBc** |
| 정확도 목표 (논문 Table I) | ≤ −43.48 dB | ≤ −50.39 / −47.83 dBc |

## 문제 목록

v0의 동작 중 **학습 모델과 다른 점 4가지**를 하나씩 따로 켜 보고 잰 손실입니다. 손실이 큰 순서입니다.

| # | 위치 (블록) | 증상 | 따로 켰을 때 ΔACPR L / R |
|---|---|---|---|
| P1 | GRU 게이트의 활성화 함수 | HW가 계산하는 sigmoid/tanh가 학습 때 쓴 함수와 다름 | +11.6 / +11.7 dB |
| P2 | 시퀀스 처리 제어 | HW의 은닉 상태 유지 방식이 golden(2,560 샘플 구간)과 다름 | +9.8 / +9.2 dB |
| P3 | 고정소수점 자료형 | 일부 값이 자료형의 표현 범위를 넘어 포화됨 | +2.7 / +5.7 dB |
| P4 | FEx (특징 추출) | FEx 내부 계산값 일부가 표현 범위를 넘어 포화됨 | +1.9 / +0.8 dB |

- 손실은 항목별로 **따로** 잰 값이라 단순히 더하면 안 됩니다. 넷을 모두 켠 v0 전체의 손실은 위 표의 "v0 동작 (예상)"입니다.
- P3을 고칠 때는 v1 규칙을 지키세요: `weight_t`, `data_t`는 **16비트 단어**로 고정, 정수부·소수부 배분은 자유, 누산기 폭은 자유.

## 직접 재현하기

모든 측정은 제공 도구로 재현할 수 있습니다. 먼저 직접 재현해서 문제를 확인한 뒤 고치세요.

1. `hw_ref.py`의 옵션(`--act`, `--fex`, `--reset_every`, `--data_t`/`--weight_t`/`--accum_t`)으로 v0의 동작을 하나씩 켜서 참조 출력을 만듭니다. 각 옵션의 의미는 `hw_ref.py` 맨 위 설명을 읽으세요.
2. `eval_pa.py`로 PA 통과 NMSE/ACPR을 재서 위 표와 비교합니다.
3. HLS C-sim 출력도 같은 방식으로 재서, Python 참조와 HLS가 같은 동작을 하는지 확인합니다 (`compare_out.py`).
