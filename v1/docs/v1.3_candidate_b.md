# v1.3: 후보 B — FEx 역수만 16,8

측정일: 2026-10-16. [v1.2 후보 A](v1.2_candidate_a.md)에서 역수 저장 형식만 변경한 두 번째 설계 후보다.
이 문서는 후보 B의 Python 모사 → C-sim 검증 → HLS 합성을 하나의 flow로 기록한다. 기존 E05(구 v1.5)는 같은 후보의 합성 단계이므로 여기에 통합했다.

## 후보 A 대비 변경

| 항목 | 후보 A (v1.2) | 후보 B (v1.3) |
|---|---|---|
| 데이터·FEx의 다른 중간값 | 16,3 | 16,3 (동일) |
| 가중치 | 16,4 | 16,4 (동일) |
| 주요 누산기 | 32,12 | 32,12 (동일) |
| 역수 `1/진폭` 저장 | **16,3** | **16,8** |
| 역수 범위 | 약 −4~4 | 약 −128~128 |
| 역수 소수부 | 13비트 | 8비트 |

전체 역수 비트폭은 16비트로 유지하면서 범위를 확보한다. 소수부 정밀도는 줄어든다.
FEx의 다른 양자화 위치, 활성화 함수, 입력·가중치, 2,560샘플 초기화 조건은 동일하다.
sqrt·역수 및 활성화 함수의 내부 double 계산도 유지한다.

### 왜 역수의 정수부를 8비트로 배분했나?

전체 7,680샘플에서 위 FEx 양자화 순서로 계산한 유효 역수의 최댓값은 약 **90.02198**이었다. 정수부 3~10비트 확인에서는 **`<16,8>`부터 역수 포화가 없었다**. `<16,7>`에서는 17개 샘플이 상한을 넘어 포화됐다. 이는 현재 테스트 입력에 대한 관찰이며 다른 입력에서도 포화가 없다는 보장은 아니다. 양자화 후 진폭이 0이 된 8개 샘플은 기존 구현대로 역수를 0으로 처리했으며 포화 횟수에서 제외했다.

`ap_fixed<16,I>`는 **signed 고정소수점**이며 I에 부호 비트가 포함된다. 약 90은 unsigned 정수 7비트로 표현할 수 있지만, signed 정수부 7비트의 양수 범위는 64 미만이다.

| 역수 형식 | 정수부 구성 | 소수부 | 표현 범위 |
|---|---|---:|---|
| `<16,7>` | 부호 1 + 나머지 정수부 6비트 | 9비트 | −64 ~ 63.998046875 |
| `<16,8>` | 부호 1 + 나머지 정수부 7비트 | 8비트 | −128 ~ 127.99609375 |

따라서 현재 signed 형식으로 약 90을 포화 없이 저장하려면 정수부가 최소 8비트 필요하다. 역수 자체는 음수가 아니므로 unsigned 형식도 별도 설계 후보가 될 수 있지만, 현재 구현은 signed를 사용한다. 이번 범위 확인으로 `<16,8>`이 최종 PA 정확도나 자원 면에서 최적이라는 결론을 내리지는 않는다. 요청에 따라 별도 역수 스윕 코드와 생성 결과 파일은 삭제했다.

## HLS 합성 결과 (기존 E05)

csynth_design 종료 코드 0, Verilog/VHDL 생성 완료. 소요 약 4분 55초.
double exp/tanh/sqrt/역수 사용이 이번 코드의 HLS 합성을 막지는 않았다.
RTL co-sim 및 Vivado 합성/배치배선은 실행하지 않았으므로 RTL 정확도와 보드 수용/타이밍은 미확인.

| 항목 | HLS 합성 결과 |
|---|---:|
| LOOP_T II | 72 |
| LOOP_T iteration latency | 268 cycles |
| 최상위 64샘플 latency | 4809 cycles / 72.135 us (15 ns 기준) |
| 최상위 호출 interval | 4608 cycles |
| Estimated clock | 10.895 ns |
| LUT 추정 | 237835 (103%) |
| FF 추정 | 179777 |
| DSP 추정 | 647 |
| BRAM_18K 추정 | 25 |

목표 II=2는 실패. 동일 클록에서 정상상태 처리율은 v0 II=2 대비 1/36.
15 ns 목표 클록을 가정한 처리율은 약 0.926 MSps이며, 실제 구현에서 확인한 처리율은 아님.
HLS 추정 LUT 103%는 구현 자원 초과 확정 판정이 아니며, v0 구현 후 자원과 직접 비교하지 않는다.

### 병목 근거

로그에 은닉 상태 write/read 간 carried dependence II violation이 기록됨.
Loop_LOOP_T_proc 보고서에서 sigmoid instance latency 28 cycles,
tanh instance latency 40 cycles. reset gate r -> candidate tanh -> next hidden의
직렬 의존성을 가진 경로에 긴 수학 함수가 위치함.
각 함수 자체의 II=1이 GRU 전체 II=1 또는 II=2를 보장하지 않음.

현재 후보는 PA 정확도 기준은 통과했지만 처리율을 포함한 완성 v1이 아니다.
다음 후보는 정확도 여유를 지키면서 활성화 함수를 LUT/구간별 고정소수점 계산으로 대체하고
FEx의 부동소수점 계산도 비용을 확인하며 대체해야 한다.
