## 원본 동작과 E24가 의도한 변경

원본의 최상위 `ResGRU()`에는 `#pragma HLS DATAFLOW`가 있다. 입력을 준비하는 `Block_entry_split_proc`와 시간 루프를 계산하는 `Loop_LOOP_T_proc` 사이에서 값과 실행 시점을 전달한다. 기존 물리 checkpoint 분석에서는 상위에 깊이 2인 FIFO 598개가 있었고, FIFO들의 FF 사용량 합계는 20,540개였다. 이 전체가 제거 가능한 계수 버퍼라는 뜻은 아니다. 필요한 데이터 보존과 호출 간 동기화 회로도 포함되므로 인자별로 확인해야 한다.

```text
원본
외부 가중치·bias → 입력 준비 단계 → 단계 간 FIFO의 저장·동기화 → 시간 루프 GRU 연산

E24가 의도한 최적화가 성공한 경우의 개념도
실행 중 고정된 가중치·bias → 필요한 저장·연결만 유지 → 시간 루프 GRU 연산
                           반복 전달용 버퍼·동기화 일부 축소 가능
```

원본은 호출별 입력값을 내부 단계에 전달할 수 있도록 구성돼 있다. 현재 테스트벤치는 계수를 한 번 로드하고 여러 블록 호출 동안 유지하므로, 반복되는 계수 전달·등록·동기화의 일부를 줄일 가능성을 검토했다. 단순히 같은 값을 전달한다고 해서 원본이 반드시 매 호출마다 외부 메모리를 다시 읽는다는 뜻은 아니다.

E24는 `multi_gru.cpp`의 `ResGRU()` 최상위 DATAFLOW 아래에 가중치, bias, PReLU, gating 등 **18개 계수 인자만 STABLE로 지정**했다. 이는 진행 중인 모든 호출이 끝날 때까지 해당 값이 변하지 않는다는 계약이다. 입력 IQ, 출력, segment_start, 은닉 상태에는 적용하지 않았다.

| 비교 항목 | 원본 | 개선 성공 시 기대 |
|---|---|---|
| 계수 취급 | 호출별 입력값을 내부 단계로 전달 | 실행 중 불변인 값으로 취급 |
| 단계 간 전달 | 필요한 버퍼에 저장하고 생산·소비 단계 동기화 | 불필요해진 등록·전달·동기화 일부 제거 가능 |
| 저장 구조 | HLS가 생성한 FIFO·로컬 저장 | 필요한 로컬 저장은 유지하며 중복 저장 축소 가능 |
| 산술·정확도 | 기존 GRU 계산 | 동일한 계수·계산·출력 유지 |
| 목표 자원 | — | 저장용 FF와 제어용 LUT 절감 |
| 추가 운용 조건 | 인터페이스 프로토콜 준수 | 모든 진행 중 호출이 완료될 때까지 계수 변경 금지 |

STABLE은 계수를 컴파일 상수로 만들거나 BRAM으로 옮기는 지시문이 아니다. 버퍼를 모두 제거하고 외부 입력을 직접 연결하는 구조도 보장하지 않는다. 최적화 결과는 HLS와 물리 구현으로 확인해야 한다.

**실제 E24에서는 의도한 전달 구조 축소를 확인하지 못했다.** HLS의 FIFO 추정치는 원본과 같았고, 최종 P&R은 LUT 41,388→41,385(−3), FF 41,088→41,105(+17), DSP 362→362였다. WNS는 +0.049→+0.056ns로 7ps 좋아졌지만 이를 전달 회로 제거의 효과로 단정할 근거는 없다. II=2와 C/RTL 7,680샘플 Q12 일치는 유지됐다. 자원 절감 성과는 사실상 없으므로 원본을 대체할 근거가 부족하다.
