# v4_post — v4.7 이후 추가 구현

[v4.7 기준 구현](../v4/result/v4.7/README.md) · [v4 전체 이력](../v4/README.md)

**현재 v4.7 이후 채택본은 T1이다.** [최종 RTL](T1/final_rtl/ResGRU.v) · [자원](T1/reports/utilization.rpt) · [타이밍](T1/reports/timing_summary.rpt) · [RTL 검증](T1/reports/rtl_validation.txt)

v4.7에서 출발해 적용한 변경을 시간순으로 정리했다. **비교 후보**는 별도로 구현해 같은 조건에서 비교한 실험이다.

- **비교 후보 — GRU 리셋 게이트 곱셈기 공유.** 층별로 따로 두었던 `r` 후단 곱셈기를 서로 다른 클럭 차례에서 번갈아 쓰도록 HLS 코드를 변경했다.
- **GRU 상태 갱신 DSP 통합.** 세 층의 상태 갱신 15곳에서 `z × (h_prev − n)`과 `+ n`을 같은 DSP 블록에서 계산하도록 RTL을 변경했다.
- **DSP 상한 설정.** 상태 갱신 통합본에 Vivado 합성 옵션 `-max_dsp 220`을 적용했다. 어떤 곱셈을 DSP와 LUT에 배정할지는 Vivado가 정한다.
- **FEx 압축 ROM.** 역제곱근과 함께 진폭·진폭 세제곱을 구간별 기준값과 차이로 저장해 조회하고, 진폭을 구하던 곱셈 두 단계를 대체했다.
- **리셋 게이트 곱셈 폭 축소.** 세 층의 `r` 후단 곱셈 15곳에서 부호 있는 15비트로 전달하던 게이트 값을 소수부 12비트의 부호 없는 값으로 표현했다.
- **비교 후보 — HLS에서 LUT 곱셈 지정.** GRU의 `r`·`z` 입력 행렬곱, 출력 FC, 잔차 연결과 `r` 후단의 일부 곱셈에 `fabric`을 지정해 HLS를 다시 실행했다. 같은 RTL에 v4.7 후처리와 상태 갱신 통합을 적용한 뒤 DSP 상한 유무를 비교했다.
- **PReLU 계수 폭 축소.** FEx 압축 ROM과 리셋 게이트 폭 축소를 적용한 DSP 220개 계열에서, PReLU 곱셈기 5개가 32비트로 부호 확장된 계수를 14비트 폭으로 읽도록 바꿨다.
- **배치·배선 전략 변경.** PReLU 계수 폭 축소본의 합성 결과를 재사용하고 Vivado 구현 전략에 `Performance_NetDelay_high`를 적용했다.
- **공유 곱셈기의 가중치 입력 폭 축소.** LUT로 구현된 공유 곱셈기 중 signed 14비트 가중치만 받는 66곳에서 가중치 입력을 29비트에서 14비트로 줄였다. 곱의 결과 폭은 29비트다.
- **FIFO 쓰기 완료 플래그 공유.** 채널별 쓰기 완료 플래그 566개를 같이 움직이는 18개 FIFO 그룹별로 하나씩 통합했다.
- **나머지 LUT 곱셈기의 입력 폭 축소.** FIFO 플래그 공유본에서 가중치와 잔차 게이트 계수를 번갈아 읽는 곱셈기 15개의 계수 입력을 29비트에서 14비트로 줄였다. 고정 가중치 7,680 I/Q 쌍과 호출마다 가중치·잔차 계수를 바꾼 512쌍에서 출력값, 기록 클럭과 호출 완료 시점이 일치했다.
- **배선 후 물리 최적화.** 입력 폭 축소본의 배선 완료 체크포인트에서 `phys_opt_design -directive Explore`를 한 번 실행했다.
- **상태 갱신 반올림 통합(T1).** HLS 생성 RTL의 상태 갱신 15곳에서 DSP 입력의 비어 있는 하위 12비트에 반올림 상수 2048을 넣어 DSP 뒤의 반올림 덧셈을 제거했다.

## 추가 구현의 자원 사용량과 타이밍

Vivado 2024.1, `xczu7ev-ffvc1156-2-e`, 목표 주기 15 ns, 면적 최적화 `AreaOptimized_high` 조건의 배선 후 결과다. `Performance_NetDelay_high`는 해당 행부터 적용한 구현 전략이다. BRAM은 36 Kib 타일 단위다.

리셋 게이트 곱셈기 공유 비교 후보의 HLS 추정치는 LUT 180,964개, FF 111,850개, DSP 465개, BRAM18 14개이며 `LOOP_T`는 II=2다.

FIFO 쓰기 완료 플래그를 공유한 뒤 전체 LUT는 420개, FF는 548개 줄었다. FF 감소분은 모두 최상위 동기화 계층에 잡혔다. DSP 220개로 목표 주기 15 ns를 충족했다.

나머지 15개 곱셈기까지 폭을 줄인 뒤 배선 후 물리 최적화를 적용하니 LUT가 1개 늘고 셋업 위반 끝점이 3개에서 0개로 줄었다. 이 단계는 FIFO 플래그 공유본 대비 LUT를 747개(1.8%) 줄였고, DSP 220개에서 WNS +0.003 ns로 15 ns를 통과했다.

T1은 직전 채택본과 같은 조건에서 LUT 258개와 FF 78개를 줄였고, 셋업 여유는 0.051 ns 늘었다. 고정 가중치 7,680 I/Q 쌍과 호출마다 가중치·잔차 계수를 바꾼 512쌍에서 출력 비트, 기록 클럭 및 호출 완료 시점이 기준과 일치했다. 별도 PA 재평가는 수행하지 않았다.
