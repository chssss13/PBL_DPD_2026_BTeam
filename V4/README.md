# V4 — v3.8 기반 직접 공급 + FEx 파이프라인 실험

## 현재 상태

**수정 후 제한적 검증 통과.** 초기 FEx 파이프라인 RTL은 미정의 출력 오류가 있었고 초기 128샘플 일치 주장은 무효다. 해당 RTL을 수정해 A→B 128샘플의 새 RTL 출력이 v3.8과 일치함을 확인했다. 다만 7,680샘플 정확도, PA 품질, 임의 정지·reset 및 보드 동작은 검증하지 않아 최종본으로 간주하지 않는다.

## 진행 흐름

1. **세현 V2 기반 → 현서 v3.5:** 3층 GRU, 은닉 크기 5, 64샘플 블록과 II=2를 유지하면서 FEx 역제곱근, sigmoid, recurrent 곱 처리 등을 개선했다.
2. **v3.6:** 598개 내부 FIFO의 제어를 최대 32개 단위로 공유했다. 데이터는 병렬로 유지했다.
3. **v3.7:** 내부 FIFO depth를 2에서 1로 축소했다.
4. **v3.8:** FIFO가 받을 수 있을 때까지 진입부 마지막 상태를 유지하고, 598개 진입부 출력 보관 레지스터를 제거했다. 블록별 파라미터 변경 시험을 수행했다.
5. **직접 공급 실험:** 1층 입력 가중치 W_ir/W_iz/W_in 75개에 대해 FIFO 출력에서 곱셈기 입력까지의 파이프라인 복사 경로를 우회했다. 별도 RTL 실험이며, 제한된 A→B 및 무작위 가중치 시험을 수행했다. 이 방법은 빈 FIFO의 출력 유지와 경계 타이밍에 의존하므로 모든 경우에 대한 동치는 미증명이다.
6. **FEx 파이프라인 추가 → V4:** 초기 stage0 저장 방식은 X 출력 오류가 있었다. 이를 이전 단계의 입력값에서 역제곱근을 계산해 stage1 에지에 저장하는 방식으로 수정했다. 수정 RTL의 A→B 128샘플 출력이 v3.8과 일치했다.

이 V4에는 후속 실험인 **FIFO 앞 가중치 채널 폭 29→14 축소는 포함되어 있지 않다.** 그 실험은 `V4_1/experiments/v38_fex_narrow_channels/`에 별도로 있다.

## 파일과 재현

- `rtl/`: 실제 실험한 HLS 생성 RTL과 v3.8 FIFO·진입부 변환, 직접 공급 75개, FEx 레지스터 수정이 반영된 Verilog. `ResGRU.v`와 `ResGRU_Loop_LOOP_T_proc.v`가 중요하다.
- `hls_reference/`: v3.8 HLS 소스 참조. **이 C++만 다시 합성하면 위 RTL 변경이 자동 적용되지 않는다.**
- `direct_weight_manifest.json`: 직접 공급으로 변경한 75개 경로.
- `rtl_sha256.json`: 보관한 RTL 파일별 SHA-256.
- `clock.xdc`: 15ns 클록 제약.
- `reports_previous_failed/`: 수정 전 기능 오류가 있던 RTL의 합성 및 배치·배선 보고서. 현재 RTL의 결과가 아니다.
- `reproduce_pnr.tcl`: 같은 RTL로 ResGRU 직접 OOC 합성·배치·배선을 재실행하는 스크립트. Vivado 2024.1 및 xczu7ev-ffvc1156-2-e 대상이며 `vivado -mode batch -source reproduce_pnr.tcl`로 실행한다. 출력 폴더가 존재하면 덮어쓰지 않는다.

이 폴더에는 독립 실행 가능한 전체 테스트벤치와 입력 벡터가 포함되어 있지 않다. 수정 후보의 시뮬레이션 자료: `V4_1/experiments/v38_fex_pipeline/fixed/direct/`; 기존 v3.8 시험: `V4_1/analysis/v38_switch_trace/`.

## 수정 전 회로 자원·타이밍 측정

아래는 수정 전 기능 오류가 있는 RTL에 대한 15ns 직접 ResGRU OOC 측정이다. **현재 V4 RTL의 측정값이 아니다.**

| 항목 | RTL 합성 | 배치·배선 |
|---|---:|---:|
| LUT | 25,787 | 23,050 |
| FF | 19,388 | 19,680 |
| DSP | 355 | 355 |
| BRAM | 0 | 0 |
| WNS | +1.540ns | +0.297ns |
| WHS | +0.073ns | +0.029ns |

배선 오류 0, setup/hold 위반 0. 직접 OOC 결과라 기존 v3.8 IP 래퍼 구현의 수치와 직접 비교하면 안 된다. 수정한 RTL의 자원·타이밍은 별도로 측정해야 한다. HLS 스케줄은 II=2를 바탕으로 했으나, RTL 변경 후 모든 입력·정지 조건에서 출력과 II가 유지된다고 주장할 수 없다.
