# PPA 이력표

모든 변경은 **한 번에 하나**, 한 행에 기록합니다. "기능검증"과 "정확도"가 비어 있는 행은 무효입니다.

- 기능검증: `compare_out.py` 결과 (참조 대비 NMSE, PASS/FAIL)
- 정확도: `eval_pa.py` 결과 (PA 통과 NMSE / ACPR L / ACPR R)
- 처리율 = Fmax / II (MSps). Fmax는 구현 후 값 (`export_impl.rpt`의 Post-Route)
- **기준은 v1.1 (첫 기능·정확도 검증 통과 버전)** 입니다. # 열에는 버전명을 기록합니다. 개선률은 기준 버전 대비로 계산하며, 미측정 항목의 개선률은 산출하지 않습니다.
- **모든 HW 수치는 팀이 정한 하나의 측정 환경에서** 잽니다 (Windows PC 또는 Linux PC·서버). v0 행도 그 환경에서 다시 구현한 값으로 채우세요 (아래 v0 값은 조교 환경 참고값).

## 표의 NMSE와 미측정 항목 읽는 법

**참조 대비 NMSE**는 구현 출력(C 또는 RTL)과 해당 버전의 Python 참조 출력 사이의 오차다. 계산식은 `10·log10(Σ|구현−참조|² / Σ|참조|²)`이며, 값이 작을수록 구현이 참조 계산과 더 가깝다. 이것은 **PA를 통과한 신호의 정확도**를 나타내는 `PA NMSE`와 다른 비교다. 참조 대비 PASS만으로 PA 정확도나 timing 통과를 의미하지 않는다.

v3 계열의 −3028.13 dB는 실제 성능 개선 크기가 아니라 출력 차이 0일 때 비교 스크립트가 반환하는 유한 수치 하한이다. 이 경우 의미는 **전체 검증 출력 불일치 0개**다.

상단 표의 LUT·FF·DSP·BRAM·Post-Route·처리율은 **실제 구현 기준**이다. `—`는 값 누락이나 0이 아니라 해당 단계 미측정이다. C 시뮬레이션만으로 II나 실제 자원·timing은 알 수 없다. II는 HLS 합성에서 확인하고, 실제 자원·주기는 Vivado 배치배선 결과에서 확인한다. 실제 주기가 없으면 구현 기준 처리율도 산출하지 않는다.
