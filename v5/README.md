# v5 전력 최적화

v5의 기준은 main `74742d7`의 [v4.6 최종 구현](../v4/result/v4.6/README.md)이다. 첫 실험은 Vivado 2024.1에서 기준 구현의 합성 후 vectorless 전력을 구하는 것이다.

1. v4.6을 구현할 때 사용한 RTL과 제약을 확보한다. v4.6의 RTL 후처리 전체를 자동으로 재생성하는 절차는 공유본에 포함되어 있지 않다. [v4 재현 자료](../v4/README.md#재현-자료와-확인-순서)
2. 15 ns 클록과 동일한 신호 활동률 및 환경 설정으로 기준과 후보의 동적 전력, 정적 전력, 총전력을 기록한다.
3. 동적 전력 추정치가 감소한 후보 중 출력 일치, 호출 지연·간격 유지, LUT·FF·DSP·BRAM 각각 증가 없음, 배치·배선 15 ns 통과를 확인한 후보를 채택한다.

기준 전력과 후보 결과는 측정 후 기록한다.

## 실험 순서와 판정

각 후보의 개선율은 **main v4.6**을 분모로 계산한다. 같은 기능과 처리 성능을 유지하면서 유의미한 개선이 확인될 때 채택한다. 개선이 작거나 자원·타이밍·출력 조건을 어긴 후보는 결과와 사유를 남기고 폐기한다.

| 순서 | 후보 | 진행 상태 |
|---|---|---|
| 1 | 기존 `tanh_comb` 15비트 출력의 기준값·보정값 테이블 | 보정 패턴을 공유하는 단순 테이블 구성 9종을 사전 검토했다. 각 구성은 32,768개 입력에서 소스 모델과 일치했다. 최소 논리 테이블 크기가 51,584비트로 기존 5,888비트의 약 8.76배여서 이 구성은 합성 후보에서 제외했다. 논리 테이블 비트 수는 FPGA LUT 사용량과 다른 지표다. |
| 2 | 입력 projection의 연산기 시분할 공유 | 첫 HLS 구현 후보 [v5.1](docs/v5.1_projection_share.md). |
| 3 | pruning·weight scaling | 재학습이 필요한 후보로 보류한다. |

1번의 사전 검토는 저장소의 `tanh_comb` 정수 연산을 모델링한 것이다. v4.6 RTL과의 등가성, Vivado 자원 및 전력은 아직 측정하지 않았다. 사전 검토는 `python v5/check_tanh_tables.py`로 재현할 수 있다.

[버전별 결과](results/README.md)에는 후보별 판정과 근거를 기록한다.
