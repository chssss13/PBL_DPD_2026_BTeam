# v5.1 GRU reset·update 게이트 공유

선택한 층에서 기존 reset의 입력·recurrent 계수와 bias를 제거한다. update 값 `z`를 후보 상태 계산 `n = tanh(x_n + z * h_n)`과 상태 갱신 `h = n + z * (h_prev - n)`에 사용한다. hidden size 5, GRU 세 층, 기존 FEx와 입출력 및 residual 구조를 유지한다.

| 후보 | 적용 범위 | 샘플당 제거되는 행렬곱 스칼라 곱셈 |
|---|---|---:|
| `layer2` | 2층 | 50 |
| `all` | 1~3층 | 150 |

첨부 ZIP의 미세조정 코드는 고정 PA, seed 4574, Adam과 데이터 분할 설정을 참고했다. ZIP의 `finetune_gru_rz.py`는 일부 입력 가중치만 묶는 방식이다. 새 스크립트는 GRU 층 자체를 공유 게이트 구조로 바꾼다. 초기 가중치는 저장소의 float DPD 체크포인트에서 가져온다. PA는 고정하며 DPD 파라미터를 미세조정한다. 검증 NMSE로 모델을 선택하고 테스트 세트에서 기존 float DPD와 후보를 같은 PA 평가기로 비교한다.

```powershell
python v5/train_shared_gate.py --scope layer2 --epochs 100 --no-early-stop --out build/v5_layer2_100
python v5/train_shared_gate.py --scope all --epochs 100 --no-early-stop --out build/v5_all_100
```

Python 시험은 float 기반이다. 하드웨어 채택 기준은 v4.6의 NMSE −45.19 dB, ACPR L/R −53.43/−50.25 dBc 및 EVM −48.90 dB다. 양자화 및 고정소수점 평가 후 이 기준을 만족한 후보에 대해 15 ns, II=2, 실제 FPGA 자원과 전력을 검증한다. [v4.6 기준](../../v4/README.md)

## 하드웨어 후보

`prepare_shared_hls.py layer2`와 `prepare_shared_hls.py all`은 v4.6의 선행 v4.2 HLS 소스에서 각 후보를 생성한다. 공유 층의 GRU 함수는 reset 입력·recurrent 행렬곱을 호출하지 않고 update sigmoid 결과를 두 곳에서 사용한다. 2층 후보는 층별 분기를 상수화하도록 층 루프를 unroll한다. 이 변경도 합성 결과에 영향을 주므로 최종 자원은 보고서로 확인한다. 테스트벤치 호환을 위해 기존 인터페이스를 유지하며, 공유 층의 사용하지 않는 reset 파라미터는 export 시 0으로 채운다.

`SHARED_SCOPE`를 `layer2` 또는 `all`로 설정하고 `vitis_hls -f v5/shared_hls.tcl`을 실행하면 기존 가중치로 C-sim과 HLS 합성을 실행한다. 재학습 완료 후 `powershell -File v5/evaluate_shared_hls.ps1 -Scope layer2` 또는 `-Scope all`을 실행하면 체크포인트를 내보내고 C-sim 결과로 PA 정확도를 평가한다. 결과는 `v5/prj_shared_<scope>/trained100_pa.txt`에 저장한다.

v4.6의 FIFO 후처리와 1층 직접 전달은 최종 RTL 단계의 변경이다. 이 HLS 후보의 수치를 v4.6 배치·배선 수치와 직접 비교해 개선율을 계산할 수 없다. 최종 비교에는 동일한 후처리 적용과 RTL co-sim, Vivado 구현이 필요하다.
