# v5.2 — E44 계수 전달 완료 상태 공유

v5.2는 **v5.1의 연산·계수·비트폭·처리 성능을 유지하면서, 같은 사건을 중복 기억하던 제어 상태를 공유한 버전**이다. C/RTL 기본·계수 변경 검증과 15ns OOC P&R을 완료했다. v5.1 대비 **FF 700개, LUT 517개, 사용 CLB 455개를 줄였고 WNS는 +0.006 → +0.091ns로 개선**됐다. DSP·BRAM은 유지했다.

## 버전과 재학습 이력

| 버전 | 변경 |
|---|---|
| v5.0 / E42 | v4.6 기능 복원 후 전체 DPD 591개 파라미터 QAT·검증 |
| [v5.1 / E43](../v5.1/README.md) | 두 번째 GRU층 가중치150개의 지연 전달 단축 |
| **v5.2 / E44** | **동일한 FIFO 묶음의 전달 완료 상태를 공유** |

v5.1의 두 번째 층 전달 단축은 그대로 유지한다. v5.2의 가중치·바이어스·PReLU·잔차 계수는 E42 재학습 결과와 동일하다. **E44에서 추가 학습·비트폭 축소·가중치 상수화는 하지 않았다.**

E42는 PA 모델을 고정하고 42개 파일에 대응하는 591개 DPD 파라미터를 학습 대상으로 삼았다. 학습/검증/테스트는23,040/7,680/7,680샘플, 상태 리셋 구간은2,560샘플이다. 검증 데이터로 epoch1을 선택했고 최종 양자화 코드가 달라진 파라미터는37개다. [학습 기록](training/training_report.json)과 선택 체크포인트를 포함한다.

## 모델과 처리 단위

```text
I/Q → FEx(6특징) → 입력 Linear(6→5) → PReLU
    → GRU1 + 잔차 → GRU2 + 잔차 → GRU3 + 잔차
    → 출력 Linear(5→2) → I/Q
```

| 설정 | 값 |
|---|---|
| GRU hidden size / 층 수 | 5 / 3 |
| 한 블록 | ResGRU 한 번의 호출에 전달하는 연속 I/Q64샘플 |
| data / bias | signed15비트, 정수부3비트, AP_RND / AP_SAT |
| weight / PReLU / 잔차 계수 | signed14비트, 정수부4비트, AP_RND / AP_SAT |
| 일반 누산 / 출력 누산 | 18/3 / 21/6, 기존 양자화 경계 유지 |
| 가중치 공급 | 런타임 입력, 호출마다 교체 가능 |
| hidden state | 층별로 별도 유지, 샘플마다 갱신, 블록 간 연속 |
| 검증 리셋 | segment_start가 설정된2,560샘플 구간 시작 |

계수는 한 블록64샘플에서 동일하게 사용한다. 일반 추론에서는 다음 블록도 같은 학습 계수를 사용하지만, 검증에서는 호출마다 다른 계수를 전달하여 잘못된 중복 쓰기나 이전 계수 혼용을 확인한다.

## 개선 대상과 원리

v5.1에는 계수 등을 전달하는 채널566개가 있다. FIFO의 full/empty 제어는 최대32채널씩 **18개 묶음**으로 공유하지만, 각 채널에는 이번 호출의 값을 이미 전달했는지 기억하는 `ap_sync_reg_channel_write_*` 상태가 개별 FF로 남아 있었다.

```text
상태0: 아직 전달하지 않음
상태1: 이미 전달함 — 같은 값을 중복 전달하지 않고 다른 채널을 기다림
```

같은 묶음 안에서는 초기값0, 클록·리셋, FIFO full 신호, 생산자의 done/continue와 상태 전이식이 동일하다. 따라서 이전 상태가 같으면 다음 상태도 같다는 귀납적 불변식을 이용한다. 정체가 없는 상황만 가정한 최적화가 아니며, FIFO full로 기다리는 경우에도 묶음 내 동일성이 유지된다.

```text
v5.1: 채널0 완료 FF ─→ 채널0 판단
      채널1 완료 FF ─→ 채널1 판단
      …
      채널31 완료 FF → 채널31 판단

v5.2: 그룹 완료 FF 하나 ─→ 같은 묶음의 모든 채널이 참조
```

원본 RTL의 초기값·상태 전이·공유 full 신호를 검사하고, 묶음 대표의 상태를 남긴 뒤 follower FF를 wire 별칭으로 연결했다. 논리 상태 수는 **566 → 18개**, 직접 줄인 상태 비트는 **548개**다. [변경·검사 기록](reports/rtl_transform.json)에 채널별 대표와 검사 결과를 보관했다. 상태 전이식의 부울 입력32조합도 확인했다.

개념적인 RTL 변경은 다음과 같다.

```verilog
// 기존: 같은 상태를 채널마다 별도 FF로 기억
reg channel0_written;
reg channel1_written;

// 변경: 대표 FF를 다른 채널도 참조
reg channel0_written;
wire channel1_written;
assign channel1_written = channel0_written;
```

**FIFO 개수·용량·데이터 저장부·가중치 최초 보관 레지스터는 유지한다.** GRU 연산식, 곱셈기 수, 양자화 경계와 계산 파이프라인도 변경하지 않는다. 실제 차이는 최상위 [ResGRU.v](rtl/ResGRU.v)의 전달 완료 제어부다. `src/`만 재합성하면 이 수동 RTL 최적화는 재생성되지 않으므로, 실제 검증·구현 대상은 `rtl/`이다.

## 실제 FF 감소 내역

| 항목 | v5.1 | v5.2 | 감소 |
|---|---:|---:|---:|
| 최상위 제어부 자체 FF | 568 | 20 | **548** |
| 물리 최적화 DSP Register 단계 추가 레지스터 | 171 | 19 | **152** |
| 전체 FF | 19,355 | 18,655 | **700** |

직접 변경한 부분은 완료 상태548개다. 추가152개는 변경된 회로를 다시 구현하면서 DSP 관련 레지스터 최적화의 추가량이 줄어든 결과이며, 계층별 보고서에서도8개 곱셈 모듈의19개씩 차이와 일치한다. DSP 개수는347개로 유지했다. [물리 최적화 요약](reports/physical_optimization_summary.json)에 원본 로그의 근거를 정리했다.

같은 상태를 참조하면 여러 채널의 완료 여부를 종합할 때 동일 조건을 반복 검사하던 논리를 합성 도구가 정리할 수 있다. 실제 입력 준비 블록 LUT는652→216개, 전체 LUT는517개 감소했다. 감소분 전체를 특정 게이트 하나의 효과로 분리한 분석은 아니다. FF·논리 감소와 후속 합성·배치·배선의 전체 결과로 자원 및 타이밍을 평가한다.

## 실제 P&R 비교

Vivado/Vitis HLS2024.1, `xczu7ev-ffvc1156-2-e`,15ns OOC 코어 조건이다. `AreaOptimized_high` 합성, `Explore` 최적화·배치·배선, 배치 후 및 배선 후 `AggressiveExplore` 물리 최적화를 사용했다.

기준은 **해시를 검증한 기존 v5.1/E43 실제 배선 결과를 재사용**했다. 동일한 기준 회로를 E44에서 다시 P&R한 수치는 아니다. 후보는 같은 옵션으로 새로 P&R했다. HLS 추정치와 실제 배선 수치를 섞지 않는다.

| 항목 | v5.1 | v5.2 / E44 | 변화 |
|---|---:|---:|---:|
| LUT | 20,130 | **19,613** | **−517 (−2.57%)** |
| FF | 19,355 | **18,655** | **−700 (−3.62%)** |
| 사용 CLB | 5,546 | **5,091** | **−455 (−8.20%)** |
| SRL LUT | 1,760 | 1,759 | −1 |
| DSP | 347 | 347 | 동일 |
| BRAM 36Kb 타일 | 7.5 | 7.5 | 동일 |
| URAM | 0 | 0 | 동일 |
| WNS | +0.006ns | **+0.091ns** | +0.085ns |
| WHS | +0.019ns | +0.019ns | 동일 |
| setup / hold / pulse 위반 endpoint | 0 / 0 / 0 | 0 / 0 / 0 | 통과 |
| 미배선 net / 배선 오류 | 0 / 0 | 0 / 0 | 통과 |

CLB는 LUT·FF 등을 묶은 FPGA 논리 블록이다. 사용 CLB 감소는 실제 배치에 사용한 블록 수 감소를 뜻하며 FF 개수와 일대일로 대응하지 않는다. 최악 경로의 출발점도 바뀌었으므로 WNS 개선 전체를 완료 FF 한 개의 지연 감소로 해석하지 않는다.

검증 범위는 내부 OOC 코어이며 보드 I/O 지연, 전체 시스템 타이밍, SDF 및 보드 실측은 포함하지 않는다. 재구현 시 실제 배선 후 결과를 다시 확인해야 한다.

## 배포 구성과 재현

`src/`는 수치 모델, `rtl/`은 실제 구현 후보, `baseline_rtl/`은 v5.1 기준 RTL이다. `golden/`에 재학습 계수42개와 입력벡터, `reference/`에 기본·스트레스 C 기준 출력, `training/`에 선택 체크포인트와 학습 기록, `reports/`에 실제 C/RTL 출력과 트랜잭션·배선 보고서를 포함한다. `PROVENANCE.json`에 각 원본의 출처와 해시를 기록했다.

Python 표준 라이브러리로 패키지 무결성과 기존 C/RTL 기록을 확인한다.

```powershell
python scripts/verify.py --archived
```

계수 전달 상태 공유를 기준 RTL에 다시 적용하고 보관된 후보와 비교한다. 원본 폴더는 수정하지 않으며 새 출력 폴더가 이미 있으면 중단한다.

```powershell
python scripts/reproduce_transform.py
```

영문·공백 없는 경로와 Vitis HLS/Vivado2024.1 환경에서 기능 검증을 재실행한다. 필요하면 `V52_HLS` 환경변수로 실행 파일을 지정한다. 이 스크립트는 새 HLS 프로젝트에서 C-sim·합성으로 인터페이스를 생성한 뒤, 보관된 기준·후보 RTL을 각각 넣어 기본·스트레스 co-sim을 실행한다.

```powershell
python scripts/run_verify.py
```

**C++ 재합성 결과만으로 v5.2를 재현했다고 판정하지 않는다.** 기존 `build/prj`가 있으면 덮어쓰지 않는다. 실제 RTL P&R은 다음처럼 별도로 실행한다.

```powershell
$env:V52_VARIANT = "candidate"
vivado -mode batch -source scripts/implement.tcl

$env:V52_VARIANT = "control"
vivado -mode batch -source scripts/implement.tcl
```

새 보고서는 `build/reports/<variant>/`, 체크포인트는 `build/checkpoints/`에 기록한다. 같은 variant 구현 폴더가 있으면 중단하며, 작업 사본을 사용하므로 보관된 RTL·ROM을 변경하지 않는다. `reports/`의 기존 결과와 재실행 결과를 구분한다. 생성 프로젝트·로그·대형 DCP는 Git 배포 대상에서 제외한다.

PyTorch가 있는 환경에서는 E42 체크포인트에서 계수를 다시 내보내고 배포 양자화 코드와 대조할 수 있다. 추가 학습은 실행하지 않는다.

```powershell
python scripts/export_weights.py --out build/exported_weights
```
