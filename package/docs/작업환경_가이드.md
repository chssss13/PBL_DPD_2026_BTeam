# 작업 환경 가이드 — Windows(내 PC) / Linux(Ubuntu PC·Linux 서버)

이 과제는 두 가지 환경 중 하나에서 진행할 수 있습니다. 어느 쪽이든 **Vitis HLS / Vivado 2024.1**을 씁니다.

| | **A. 내 PC (Windows)** | **B. Linux (개인 Ubuntu PC 또는 쓸 수 있는 Linux 서버)** |
|---|---|---|
| 툴 설치 | 직접 설치 (§A-1) | 직접 설치 (서버에 이미 있으면 그대로 사용) |
| 접속 | 내 PC에서 바로 | Ubuntu PC: 바로 / 서버: SSH (VS Code Remote-SSH 권장) |
| 명령 형식 | PowerShell (§3 대응표) | bash (안내문·README 그대로) |
| 장점 | 설치만 하면 언제든 작업 | 안내문 명령 그대로, 서버는 접속이 끊겨도 작업 유지 |
| 주의 | 한글 경로, 메모리, 절전 | 서버라면 다른 사용자와 자원 공유, 기본 셸이 csh일 수 있음 |

- **macOS**에는 Vitis / Vivado가 설치되지 않습니다. 팀원의 Windows PC나 쓸 수 있는 Linux 환경에서 작업하세요. Linux 서버가 있다면 Mac에서도 SSH로 접속할 수 있습니다.
- 연구실 서버 계정은 제공하지 않습니다. 각자 환경을 준비하세요.
- 팀 안에서 환경이 섞여도 되지만, **PPA를 재는 환경은 팀당 하나로 정해야 합니다** (§5).

### A-3. Python (가상환경 venv)

`tools/`의 Python 도구는 아래 패키지가 필요합니다.

| 도구 | 필요한 패키지 |
|---|---|
| `hw_ref.py`, `compare_out.py` | numpy |
| `eval_pa.py` (PA 대리모델로 정확도 측정) | numpy, scipy, pandas, matplotlib, **torch (CPU)** |

#### 왜 venv(가상환경)를 쓰나

venv는 **이 과제 전용 Python 설치 공간**입니다. 시스템 Python에 바로 `pip install`하지 않고 venv를 따로 만드는 이유는 다음과 같습니다.

1. **Python이 여러 개 잡힐 수 있습니다.** Vitis HLS Command Prompt는 툴 환경을 설정하면서 Xilinx 쪽 프로그램 경로를 PATH 앞에 넣습니다. venv 없이 실행하면 torch가 없는 다른 Python이 실행되어 `ModuleNotFoundError: torch`가 날 수 있습니다. venv를 활성화하면 **항상 이 과제용 Python이 맨 앞**에 옵니다.
2. **다른 과목·프로젝트와 버전이 충돌하지 않습니다.** torch, numpy 버전을 이 과제에 맞춰 고정할 수 있고, 다른 프로젝트의 패키지 업데이트에 영향을 받지 않습니다.
3. **망가져도 지우고 다시 만들면 끝입니다.** venv 폴더 하나만 지우면 시스템 Python은 그대로입니다.
4. **팀원끼리 같은 환경**을 만들기 쉽습니다. 아래 명령을 그대로 따라 하면 같은 구성이 됩니다.

#### 처음 한 번: Python 설치 → venv 만들기 → 패키지 설치

**① Python 설치** (이미 있으면 버전만 확인)
- python.org에서 **Python 3.11 또는 3.12**를 설치합니다 (torch CPU 버전이 지원하는 범위).
- 설치 첫 화면에서 **"Add python.exe to PATH"** 를 체크합니다.
- 확인 (일반 명령 프롬프트):

```bat
py --version
```

**② venv 만들기** — 위치는 **패키지 폴더 밖**을 권장합니다 (예: `D:\work\venv`).
- 패키지 폴더 안에 만들면 결과를 복사·압축·제출할 때 수백 MB의 torch 파일이 함께 딸려 갑니다.
- 패키지를 여러 벌 복사해도 venv 하나를 같이 쓸 수 있습니다.
- 경로에 **한글·공백이 없게** 합니다.

```bat
py -3.12 -m venv D:\work\venv
```

**③ 활성화** — 프롬프트 앞에 `(venv)`가 붙으면 성공입니다.

```bat
D:\work\venv\Scripts\activate
```

> PowerShell에서는 `D:\work\venv\Scripts\Activate.ps1`입니다. "스크립트를 실행할 수 없습니다" 오류가 나면 PowerShell에서 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`를 한 번 실행하거나, 명령 프롬프트(cmd)를 쓰세요.

**④ 패키지 설치** (활성화된 창에서)

```bat
python -m pip install --upgrade pip
```

```bat
pip install numpy pandas scipy matplotlib
```

```bat
pip install torch --index-url https://download.pytorch.org/whl/cpu
```

GPU는 필요 없습니다. CPU 버전 torch로 충분합니다 (평가만 하고 학습은 하지 않음).

**⑤ 확인**

```bat
python -c "import numpy, scipy, pandas, torch; print('OK', torch.__version__)"
```

#### 그다음부터: 창을 열 때마다 활성화

venv 활성화는 **그 창에만** 적용됩니다. 새 명령 창(Vitis HLS 2024.1 Command Prompt 포함)을 열 때마다 먼저 실행하세요.

```bat
D:\work\venv\Scripts\activate
```

한 창에서 Vitis 명령과 Python 명령을 모두 쓰는 순서:

```bat
:: 시작 메뉴 "Vitis HLS 2024.1 Command Prompt"
cd /d D:\work\lw_resgru
D:\work\venv\Scripts\activate
where python
```

`where python`의 **첫 줄이 `D:\work\venv\Scripts\python.exe`** 이면 준비 완료입니다. 다른 경로가 먼저 나오면 활성화가 안 된 것입니다.

- 끝낼 때는 `deactivate` (창을 닫아도 됩니다)
- venv가 꼬였으면 `D:\work\venv` 폴더를 지우고 ②부터 다시 하면 됩니다.

## B. Linux (개인 Ubuntu PC / Linux 서버)

Ubuntu PC에서 직접 작업한다면 B-1은 건너뛰고 B-2로 가세요.

### B-1. 접속 (Linux 서버를 쓰는 경우)

| 내 PC | 권장 | 대안 |
|---|---|---|
| Windows | **VS Code + Remote-SSH 확장** | MobaXterm (터미널 + 파일 전송 + GUI 창 표시) |
| macOS | **VS Code + Remote-SSH 확장** | 터미널 `ssh` + Cyberduck(파일 전송) |
| Linux | VS Code + Remote-SSH 또는 터미널 `ssh` | |

VS Code Remote-SSH 사용법:

1. VS Code 확장(Extensions)에서 **Remote - SSH** 설치
2. 왼쪽 아래 `><` → **Connect to Host** → `계정@서버주소`
3. **File → Open Folder**로 서버의 내 작업 폴더 열기
4. 터미널(**Ctrl + `**)을 열고 **먼저 `bash` 입력** (서버 기본 셸이 csh/tcsh이면 안내문의 명령이 그대로 안 될 수 있음)
5. 파일 올리기·내려받기: VS Code 탐색기에 끌어다 놓기 / 오른쪽 클릭 → Download

> 매번 bash로 열려면 VS Code 설정에서 `terminal.integrated.defaultProfile.linux`를 `bash`로 지정

Vitis HLS·Vivado의 GUI 창(스케줄 뷰어, 타이밍 경로)이 필요하면 MobaXterm(Windows) 또는 XQuartz + `ssh -X`(macOS)로 접속합니다. 기본은 리포트 파일로 확인하세요.

### B-3. 오래 걸리는 작업

접속이 끊겨도 계속 돌도록 `nohup … &`로 실행합니다.

```bash
STEPS="csynth impl" nohup vitis_hls -f scripts/run_resgru.tcl > results/impl.log 2>&1 &
```

- 진행 확인: `tail -n 3 results/impl.log`, 내 작업 목록: `ps -u $USER -o pid,etime,args | grep vitis`
- 서버에 `tmux`가 있으면 `tmux new -s hls`로 들어가 작업하면, 다시 접속해 `tmux attach -t hls`로 화면까지 이어 볼 수 있습니다.
- 여러 사람이 함께 쓰는 서버라면 구현(impl)은 동시에 하나만 돌리고, 메모리 여유가 적을 때는 기다려 주세요 (구현 1회에 메모리 약 4 GB).
- 읽기 전용 폴더에서 툴을 실행하면 `tee: vitis_hls.log: Permission denied`가 납니다 → 내 작업 폴더에서 실행

## 3. 명령어 대응표: bash ↔ Windows PowerShell

안내문과 README의 명령은 bash 형식입니다. Windows에서는 아래처럼 바꿔 쓰세요. Python 명령은 `/`를 그대로 써도 됩니다.

| bash (Linux) | Windows PowerShell |
|---|---|
| `vitis_hls -f scripts/run_resgru.tcl` | 같음 (툴 경로가 잡힌 창에서) |
| `STEPS="csynth impl" vitis_hls -f …` | `$env:STEPS="csynth impl"; vitis_hls -f …` |
| `RESET_ARG=1 vitis_hls -f …` | `$env:RESET_ARG=1; vitis_hls -f …` |
| (환경변수 지우기) | `Remove-Item Env:STEPS, Env:RESET_ARG` |
| `cd opendpd_min && python ../tools/eval_pa.py …; cd ..` | `cd opendpd_min; python ../tools/eval_pa.py …; cd ..` |
| `tail -n 20 파일` | `Get-Content 파일 -Tail 20` |
| `grep "Pipelining result" 파일` | `Select-String "Pipelining result" 파일` |
| `nohup 명령 > log 2>&1 &` | 새 창에서 실행하고 창을 닫지 않음 |

> Windows `cmd`(명령 프롬프트)에서는 환경변수를 `set STEPS=csynth impl`처럼 씁니다.

## 5. PPA 수치의 기준 — 중요

같은 소스와 같은 2024.1이라도 **환경(OS, CPU, PC)에 따라 구현 결과가 조금 다를 수 있습니다.**

1. **팀마다 PPA 측정 환경을 하나로 정합니다** (예: "팀원 ○○의 Windows PC" 또는 "○○ Linux 서버"). 다른 환경에서 잰 숫자를 한 표에 섞지 마세요.
2. **v0를 그 환경에서 한 번 구현해 기준값으로 기록**합니다 (PPA 이력표의 v0 행). 안내문의 v0 수치(LUT 46,544, 16.659 ns 등)는 조교 환경(연구실 Linux 서버)의 참고값입니다.
3. 개선률은 **같은 환경에서 잰 v1 대비**로 계산합니다.
4. 최종 비교(두 팀 간)는 조교가 두 팀의 최종 설계를 **같은 환경에서 다시 구현**해 확인합니다. 최종 제출물은 소스와 빌드 스크립트만으로 다시 돌아가야 합니다.

정확도(NMSE, ACPR)는 Python으로 계산하므로 어느 환경에서나 같은 값이 나옵니다.

참고로 조교가 v0를 두 환경에서 구현해 본 결과입니다. 자원은 거의 같고, 타이밍은 0.5 ns 정도 차이가 났습니다.

| 환경 | LUT | FF | DSP | Post-Route | csynth+impl 시간 |
|---|---|---|---|---|---|
| 조교 연구실 서버 (Linux) | 46,544 | 49,551 | 648 | 16.659 ns | — |
| Windows 11 PC | 46,646 | 49,546 | 648 | 17.129 ns | 약 1시간 |

구현 한 번에 1시간 가까이 걸리므로, **C-sim과 csynth로 먼저 걸러 내고 구현은 꼭 필요할 때만** 돌리세요.

| `vitis_hls`를 찾을 수 없음 | 툴 경로 미설정 → Windows: "Vitis HLS 2024.1 Command Prompt", Linux: settings64.sh를 source |
| `Ambiguous output redirect`, `if: Expression Syntax` (서버) | csh에서 bash 명령을 실행함 → `bash` 입력 후 다시 |
| `tee: vitis_hls.log: Permission denied` (서버) | 쓰기 권한 없는 폴더에서 실행 → 내 작업 폴더로 이동 |
| 접속이 끊겼더니 합성이 사라짐 (서버) | `nohup … &` 없이 실행 → nohup 또는 tmux |
| 경로 관련 에러, 글자 깨짐 (Windows) | 경로에 한글·공백 → `D:\work\…`로 옮기기, TEMP 변경 |
| **설치 프로그램이 내려받기 시작 1분 안에 오류 없이 꺼짐** (Windows, "프로그램 호환성 관리자" 창이 뜨기도 함) | ① 한글 임시 경로 → §A-1의 관리자 PowerShell 방식으로 실행 ② 그래도 꺼지면 메모리 부족 → 작업 관리자에서 메모리를 많이 쓰는 프로그램 확인 (`WavesSvc64.exe` 사례) |
| 설치·구현이 원인 없이 꺼짐 (Windows) | 이벤트 뷰어 → Windows 로그 → 시스템에서 "Resource-Exhaustion-Detector"(메모리 부족) 기록 확인 |
| impl 단계에서 디바이스·라이선스 에러 | xczu7ev를 쓸 수 있는 라이선스가 없음 → 조교에게 즉시 문의 |
| 합성이 중간에 사라짐 (Windows) | 절전·재부팅·창 닫힘 → 전원·절전 설정 확인 |
| `ModuleNotFoundError: torch` (또는 numpy, scipy) | venv가 활성화되지 않은 창 → `D:\work\venv\Scripts\activate` 후 `where python` 확인. 처음이라면 §A-3대로 venv 생성·설치 |
| `pip install torch`가 "No matching distribution" | Python 버전이 torch가 지원하지 않는 버전 → Python 3.11 / 3.12로 venv를 다시 만들기 |
| GUI가 새 Unified IDE로 열림 / `Can only use '-p' with '-classic' HLS IDE` | §A-2: Command Prompt에서 `vitis_hls -classic -p prj_resgru` |
| ACPR이 안내문 숫자와 15 dB 다름 | 직접 계산함 → 반드시 `eval_pa.py`로 측정 |
