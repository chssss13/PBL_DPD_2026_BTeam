# v5.1 — E43 가중치 전달 경로 최적화

v5.1은 **E42에서 재학습·검증한 v5.0 모델의 계수를 유지하면서, 두 번째 GRU층의 가중치 전달 지연을 줄인 버전**이다. 기본 출력·계수 변경 검증과 15ns OOC 배치·배선을 완료했다. 같은 구현 흐름의 v5 기준 대비 LUT는 **21,818 → 20,130개(−7.74%)**로 줄었으며, DSP와 BRAM 사용량은 유지했다.

FF는 56개, 사용 CLB는 227개 증가했다. WNS는 +0.006ns로 통과했지만 여유가 6ps에 불과하다. LUT 절감과 물리 배치 면적·타이밍 여유를 구분해 평가해야 한다.

## 버전과 학습 이력

| 버전 | 변경 범위 | 학습 계수 |
|---|---|---|
| sehyeon v4.6 | FEx 역제곱근 ROM, FIFO·계수 전달 경로 최적화 | 기존 학습 계수 |
| v5.0 / E42 | v4.6 기능을 복원하고 전체 DPD 파라미터 재학습·검증 | 입력층·GRU 3층·잔차 게이트·PReLU·출력층의 총 591개 파라미터 |
| **v5.1 / E43** | **두 번째 GRU층 가중치 150개의 전달 지연 축소** | **E42 계수를 그대로 사용. E43 추가 학습 없음** |

E42는 PA 대리모델을 고정하고 42개 계수 파일에 대응하는 591개 파라미터를 양자화 인지 학습 대상으로 삼았다. 학습·검증·테스트는 각각 23,040 / 7,680 / 7,680샘플이며, 검증 데이터로 epoch를 선택했다. 선택된 epoch는 1이고 최종 양자화 코드가 바뀐 파라미터는 37개다. 테스트 데이터는 epoch 선택에 사용하지 않았다. [학습 기록](training/training_report.json), [학습 이력](training/history.json), [선택 체크포인트](training/best_master.pt)를 포함한다.

기존 v4.6 최종 RTL 전체가 저장소에 없었으므로, E42는 보관된 v4.7 RTL에서 두 번째 층 변경 150개를 되돌려 v4.6 기능을 복원했다. C/RTL 출력과 호출 성능을 검증하고 물리 타이밍을 보정한 결과를 v5.0으로 확정했다. v5.1은 그 기준 위에 두 번째 층 단축을 다시 적용하여 **재학습된 계수로 기능과 물리 구현을 재검증한 결과**다. 역사적인 v4.6 수치와 이번 동일 조건 P&R 수치를 섞어 비교하지 않는다.

## 모델과 처리 단위

```text
I/Q → FEx(6개 특징) → 입력 Linear(6→5) → PReLU
    → GRU 1층 + 잔차 → GRU 2층 + 잔차 → GRU 3층 + 잔차
    → 출력 Linear(5→2) → I/Q
```

| 설정 | 값 |
|---|---|
| GRU hidden size / 층 수 | 5 / 3 |
| 한 블록 | 한 번의 ResGRU 호출에 전달하는 연속 I/Q 64샘플 |
| data / bias | signed 15비트, 정수부 3비트, AP_RND / AP_SAT |
| weight / PReLU / 잔차 계수 | signed 14비트, 정수부 4비트, AP_RND / AP_SAT |
| 일반 누산 | signed 18비트, 정수부 3비트 |
| 출력층 누산 | signed 21비트, 정수부 6비트 후 최종 data_t 변환 |
| 가중치 공급 | 런타임 입력. 학습 가중치 상수화 없음 |
| 검증 상태 초기화 | 2,560샘플마다 구간 시작에서 초기화 |

한 블록에는 GRU 세 층을 포함한 전체 모델 처리가 들어 있다. 블록 0은 샘플 0~63, 블록 1은 샘플 64~127에 해당한다. 각 층은 서로 다른 hidden state를 사용하고 샘플마다 갱신한다. 블록이 바뀌어도 hidden state는 이어지며, `segment_start`가 설정된 구간 시작에서 초기화한다.

한 블록의 계수는 64샘플에서 동일하게 사용한다. 일반 추론에서는 다음 블록도 같은 학습 계수를 사용하지만, 인터페이스는 호출마다 계수를 교체할 수 있다. FIFO는 계수의 임시 전달·저장 경로이며 학습 모델의 원본 저장소를 대체하는 개념이 아니다.

## FIFO와 가중치 보관 수명

공통 입력 준비 블록은 각 층의 계수를 여러 FIFO 채널로 전달한다. 층마다 FIFO가 하나씩 있다는 뜻은 아니다. 채널들은 공통 생산자 완료 이벤트에 따라 동기화되며, 실제 쓰기는 full/empty와 핸드셰이크 조건을 따른다. 층별 계산이 끝날 때마다 다음 층 계수를 순서대로 불러오는 구조가 아니다.

계수를 받는 시점과 사용하는 시점은 다르다. 뒤쪽 GRU층은 앞 층 결과를 받은 뒤 연산하므로 계수의 마지막 사용도 늦어질 수 있다. FIFO가 다음 호출의 계수로 넘어가는 시점은 공통 소비 블록의 핸드셰이크로 결정된다. 첫 층의 곱셈 완료 자체가 FIFO 전체 교체 신호는 아니다.

파이프라인에서는 이전 호출의 출력이 모두 끝나기 전에 다음 호출을 준비할 수 있다. 따라서 FIFO 직접 참조를 적용하려면 **계수의 마지막 사용 시점까지 올바른 값이 유지되는지** 확인해야 한다. 이전 FIFO 항목은 다음 쓰기에서 덮어써질 수 있지만, 이미 끝난 곱셈에는 과거 계수가 필요하지 않다. 해당 곱셈 결과는 후속 데이터 경로로 전달된다.

## 변경 원리

HLS는 각 반복에서 받은 값이 실제 연산 시점에 도착하도록 전달 레지스터를 생성한다. 이 단계들은 계산 데이터와 계수의 시점을 맞추며, 지연이 길면 LUT를 시프트 레지스터로 쓰는 SRL로 구현될 수 있다.

가중치는 블록 내에서 동일하므로, 최초 보관 위치의 값이 필요한 연산 시점까지 유효하다면 뒤쪽 복사본을 읽지 않아도 된다. v5.1은 두 번째 GRU층의 입력·순환 가중치 **6개 행렬 × 5 × 5 = 150개**에서 이 조건을 이용한다.

```text
v5.0: FIFO → 최초 보관 레지스터 → 지연 복사 1 → … → 지연 복사 N → 곱셈기
v5.1: FIFO → 최초 보관 레지스터 ─────────────────────────────→ 곱셈기
```

**최초 보관 레지스터와 계산 파이프라인은 유지한다.** 곱셈기의 계수 선택 연결만 바꾸고, 사용하지 않게 된 뒤쪽 저장 경로는 합성 도구가 제거하도록 한다. 배포 RTL에 일부 미사용 선언·할당이 남아 있어도 실제 합성 회로에서 제거될 수 있다. 모든 가중치 경로의 지연 단계 수가 같다는 뜻은 아니다.

실제 연결의 한 예는 다음과 같다. 곱셈기 입력 포트 이름만 가독성을 위해 단순화했다.

```verilog
// v5.0
mul_w = p_read_313_reg_113448_pp0_iter3_reg;
// v5.1
mul_w = p_read_313_reg_113448;
```

변경 목록은 [rtl_transform.json](reports/rtl_transform.json), 실제 연결은 [최종 소비 블록 RTL](rtl/ResGRU_Loop_LOOP_T_proc.v)에 있다. 연산식, 반올림·포화 경계, 비트폭, 가중치 값과 hidden-state 갱신은 변경하지 않았다. FIFO 개수나 층 수를 줄인 최적화도 아니다.

### 두 번째 층의 선택 근거

첫 번째 층의 입력 가중치 75개에는 v4.6에서 이미 FIFO 직접 전달이 적용돼 있었다. 첫 층의 모든 계수 보관 경로가 제거됐다는 뜻은 아니다. 두 번째 층은 긴 전달 경로가 남아 있었고, 이전 v4.7에서 SRL 절감이 확인된 범위였다.

세 번째 층까지 확장한 과거 v4.7-1 실험에서는 LUT 98개 감소에 FF 1,471개 증가가 동반됐다. 이 기록을 바탕으로 v5.1에서는 두 번째 층으로 범위를 한정했다. 다른 층에 적용할 수 없다는 의미가 아니라, 실제 자원·타이밍 결과를 근거로 선택한 범위다.

| 검증 | 조건 | 결과 |
|---|---|---|
| C-sim | 재학습 계수, 7,680샘플 | v5 기준 Q12 출력 완전 일치 |

| 기준·후보 RTL 스트레스 | 각 5,120샘플, 80회 호출 | C 기준과 완전 일치 |
| 기준·후보 RTL 상호 대조 | 기본·스트레스 | Q12 불일치 0 |
| 스트레스 계수·입력 | 호출마다 591개 계수 항목에 의사난수 변화, I/Q 회전, 2,560샘플 리셋 경계 통과 | 통과 |

스트레스 시험은 이전·다음 호출 계수가 잘못 섞이는 경우를 확인하기 위한 것이다. 제공된 호출 프로토콜·벡터와 추가 시험 범위의 검증이며, 임의의 모든 외부 프로토콜에 대한 형식 증명은 아니다.

| 정상 상태 성능 | v5 기준 | v5.1 |
|---|---:|---:|
| 64샘플 호출 지연 | 144클록 | 144클록 |
| 호출 간격 | 134클록 | 134클록 |
| 15ns 기준 호출 간격 환산 처리율 | 31.8408 MSps | 31.8408 MSps |

처리율은 `64 / (134 × 15ns)`로 계산했다. 이상적인 샘플 II=2의 `1 / (2 × 15ns) = 33.3333 MSps`와 구분한다. 호출 지연은 한 샘플의 독립 처리 시간이나 호출 간격과 동일한 지표가 아니다.

## 실제 P&R 결과

AMD Vivado/Vitis HLS 2024.1, `xczu7ev-ffvc1156-2-e`, 15ns OOC 코어 조건이다. 양쪽 모두 `AreaOptimized_high` 합성, `Explore` 최적화·배치·배선, 배치 후 및 배선 후 `AggressiveExplore` 물리 최적화를 사용했다. 아래 수치는 HLS 추정치가 아닌 **같은 흐름으로 새로 구현한 배선 후 결과**다.

| 항목 | v5 기준 | v5.1 / E43 | 변화 |
|---|---:|---:|---:|
| 전체 LUT | 21,818 | **20,130** | **−1,688 (−7.74%)** |
| SRL LUT | 3,039 | **1,760** | **−1,279** |
| FF | 19,299 | 19,355 | +56 (+0.29%) |
| DSP | 347 | 347 | 동일 |
| BRAM 36Kb 타일 | 7.5 | 7.5 | 동일 |
| URAM | 0 | 0 | 동일 |
| 사용 CLB | 5,319 | 5,546 | +227 (+4.27%) |
| WNS | +0.013ns | **+0.006ns** | −0.007ns |
| WHS | +0.019ns | +0.019ns | 동일 |
| setup / hold / pulse 위반 endpoint | 0 / 0 / 0 | 0 / 0 / 0 | 통과 |
| 미배선 net / 배선 오류 | 0 / 0 | 0 / 0 | 통과 |

SRL 감소는 전체 LUT 절감의 약 76%에 해당한다. 나머지 LUT 순감소 원인은 별도로 분리하지 않았다. FF·CLB 증가와 타이밍 여유 감소가 있어 전체 물리 면적이 개선됐다고 해석할 수는 없다. 실험에서 사전에 정한 LUT 5% 이상 절감·FF 증가 1% 이하·DSP/BRAM 비증가 기준은 통과했다.

물리 검증은 내부 OOC 코어 범위다. 보드 I/O 지연, 전체 시스템 타이밍, SDF 및 보드 실측은 포함하지 않는다. 재구현 시 같은 결과가 자동 보장되는 것은 아니므로 실제 배선 후 수치를 다시 확인해야 한다.

### 실제 RTL P&R 재실행

아래 스크립트는 보관된 RTL을 직접 합성·배치·배선한다. 작업 사본을 `build/`에 만들므로 원본 ROM·RTL을 변경하지 않는다. 같은 variant의 구현 폴더가 있으면 중단한다.

```powershell
$env:V51_VARIANT = "candidate"
vivado -mode batch -source scripts/implement.tcl

$env:V51_VARIANT = "control"
vivado -mode batch -source scripts/implement.tcl
```

새 결과는 `build/reports/<variant>/`, 체크포인트는 `build/checkpoints/`에 저장된다. 배포에 포함된 기존 `reports/`와 구분한다. 기능 검증까지 수행하려면 위의 `run_verify.py`도 별도로 실행해야 한다. 생성 프로젝트·로그·대형 DCP는 Git 배포 대상에 포함하지 않는다.

### 체크포인트에서 계수 다시 내보내기

PyTorch가 설치된 환경에서 실행한다. 체크포인트는 기존 OpenDPD 전체 모델 객체가 아닌, E42의 고정소수점 QAT 모델 `state_dict`와 선택 epoch·검증 지표를 담는다. 실제 추론에는 `golden/weights/`의 양자화된 계수를 사용한다.

```powershell
python scripts/export_weights.py --out build/exported_weights
```

이 명령은 저장된 학습 결과를 내보낼 뿐 추가 학습을 실행하지 않는다. 배포 계수와 양자화 코드가 같은지도 검사한다.
