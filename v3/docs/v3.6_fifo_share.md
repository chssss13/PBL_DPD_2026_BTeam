# v3.6: 전달 FIFO 32개 단위 제어 공유

2026-11-15. 기준은 **Accepted v3.5**이며, 아래 수치는 완료된 해당 후보의 전체 flow 결과다. 판정: **accepted**.

## 변경 목적과 코드

부모는 채택된 v3.5다. 진입부 `Block_entry_split_proc_U0`와 샘플 연산부 `Loop_LOOP_T_proc_U0` 사이에 있는 scalar propagation FIFO의 중복 제어를 줄였다. C++ 연산식을 수정한 버전이 아니라, **Vitis HLS가 생성한 Verilog에 구조 검증을 거친 후처리를 적용한 버전**이다.

v3.5의 routed 계층 보고서를 중복 없이 집계하면 전달 FIFO 598개가 LUT 9,649개, FF 20,540개를 사용했다. FF는 전체 41,308개의 약 49.7%다. 이 비용에는 데이터 저장과 제어가 함께 포함되므로 전부 제거 가능한 자원으로 보지는 않았다.

| v3.5의 구역 | LUT | FF | DSP |
|---|---:|---:|---:|
| 진입부 | 4,474 | 9,201 | 0 |
| 샘플 연산부 | 23,468 | 10,967 | 355 |
| 두 처리부 사이 전달 FIFO | 9,649 | 20,540 | 0 |
| 최상위 자체 로직 | 0 | 600 | 0 |
| 전체 | 37,311 | 41,308 | 355 |

위 값은 [v3.5 routed 계층 보고서](../results/v3.5/evidence/impl/reports/detail/ResGRU_utilization_hierarchical_routed.rpt)의 직계 구역을 집계한 것이다. 상위 모듈과 그 하위 모듈의 자원을 다시 더하지 않는다.

### 공유하는 부분과 유지하는 부분

598개 채널의 데이터 저장부는 각각 유지하고, 최대 32개씩 묶어 주소·점유 수·full/empty 상태와 push 제어를 공유한다. 32개 그룹 18개와 나머지 22개 그룹 1개, 총 **19개 제어부**를 만든다.

```text
변경 전: 데이터 저장부 598개 + 채널별 FIFO 제어부 598개
변경 후: 데이터 저장부 598개 + 그룹별 FIFO 제어부  19개

한 그룹:
  공통 제어(addr, push, occupancy, full_n, empty_n)
       ├─ 채널 0의 깊이 2 저장부
       ├─ 채널 1의 깊이 2 저장부
       └─ ... 최대 32개 채널의 깊이 2 저장부
```

데이터를 하나의 좁은 버스로 직렬 전송하지 않는다. 채널별 비트폭, 깊이 2, 데이터 순서 및 읽기 지연을 유지한다. RTL 선언 기준 한 슬롯의 payload 폭 합계는 **12,941비트**다. 깊이 2의 선언상 저장 용량은 25,882비트이며, 상수 전파와 합성 최적화 이후의 물리 FF 개수와 같은 숫자는 아니다.

공유 제어부의 기본 동작은 기존 FIFO와 같다.

```verilog
push = full_n  & wr;
pop  = empty_n & rd;
// push만 발생: 점유 수 증가
// pop만 발생: 점유 수 감소
// 동시에 발생하거나 둘 다 없음: 점유 수 유지
```

### 공유 가능 조건의 확인

[RTL 변환 코드](../experiments/v3.6/rtl_transform.py)는 임의로 FIFO 이름만 묶지 않고 다음 구조를 검사한다. 조건이 다르거나 대상이 598개가 아니면 변환을 중단한다.

1. 동일 clock/reset과 동일한 초기 full/empty 상태를 사용하는지 확인한다.
2. 모든 대상의 read가 `Loop_LOOP_T_proc_U0_ap_ready`인지, read/write clock enable이 동일한지 확인한다.
3. 생산자 완료 신호가 같고, 각 채널의 write 동기화 레지스터가 같은 reset·done/continue 조건과 같은 형태의 상태 전이식을 갖는지 확인한다.
4. 비트폭과 모듈 이름을 제외한 FIFO 제어 RTL이 동일한지 확인한다.

이 조건 아래에서는 같은 상태에서 시작한 제어부들이 같은 read와 생산자 완료 조건에 따라 계속 같은 상태로 움직인다는 귀납 관계를 이용할 수 있다. 그룹 대표 제어부의 상태를 다른 채널에 연결하되 payload는 각자의 입력을 저장한다. 이는 **국소 구조 조건에 대한 검사와 동등성 논리**이며, 전체 회로의 순차 동등성을 formal 도구로 증명한 결과는 아니다.

### 논문과 실제 적용 범위

근거는 Kelley et al., **Removing Overhead from High-Level Interfaces**, DAC 2012, pp. 783–789, DOI `10.1145/2228360.2228502`다. 순차 도달가능 상태를 분석해 유연한 인터페이스의 불필요한 제어와 버퍼 비용을 제거하는 연구다. 기술 내용은 저자의 [학위논문 Chapter 3](https://www-vlsi.stanford.edu/people/alum/pdf/1208_Kelly_HighLevelDigitalInterfaces.pdf)에서 확인했다.

본 버전의 32개 단위 제어 공유는 이 방향을 참고한 자체 변형이다. 논문의 SAT 기반 도달가능 상태 분석기를 구현하거나 그 실험 결과를 재현한 것은 아니다. 논문에서 보고한 절감률을 본 설계의 예상 절감률로 사용하지 않았다.

## RTL 변환과 실제 구현 흐름

1. v3.5와 동일한 C++로 C 검증과 HLS 합성을 실행하고 LOOP_T II=2를 확인한다.
2. 생성된 `syn/verilog/ResGRU.v`의 대상 구조를 검사한 뒤 제어 공유를 적용한다.
3. 변경한 RTL로 전체 7,680샘플 co-simulation을 수행한다.
4. HLS에서 IP를 export한 뒤, export가 다시 생성한 top RTL을 **co-simulation에서 검증한 RTL로 교체**한다.
5. v3.5의 장치·클록·합성 directive·구현 흐름을 사용하는 Vivado 스크립트로 실제 합성·배치배선을 수행한다.

HLS의 `export_design`은 내부 설계 정보로 RTL을 다시 생성하므로 export 전에 Verilog만 고치면 최종 IP에 수정이 남지 않을 수 있다. 이 버전은 [IP 구현 준비 스크립트](../scripts/prepare_shared_impl.py)에서 export 후 파일을 설치한다. [구현 RTL 해시 기록](../experiments/v3.6/implementation_rtl_audit.json)에 저장된 변환 RTL과 co-simulation RTL의 SHA-256은 모두 다음과 같다.

```text
cabbc5d616056946af2cde700cca87e1ba6c4d4768b8e67ab96b005a5ac08160
```

자동 생성된 교착 감시기는 기존 FIFO 인스턴스 경로의 `if_empty_n`, `if_full_n`, `if_read`, `if_write`를 참조한다. 변환 후에도 이 관측 경로를 유지하도록 별칭을 추가했으며, 감시기를 끄는 방식으로 시뮬레이션을 통과시키지 않았다.

## FF 중심 Area Breakdown

2026-11-15 분석. 근거는 **배치배선 완료 후**의 [v3.6 계층별 자원 보고서](../results/v3.6/evidence/impl/reports/detail/ResGRU_utilization_hierarchical_routed.rpt)와 [전체 자원 보고서](../results/v3.6/evidence/impl/reports/detail/ResGRU_utilization_routed.rpt)다. HLS 추정치가 아니다. 상위와 하위 모듈을 중복 합산하지 않고 top의 직계 구역을 집계했다.

### 현재 FF 구성

비중의 분모는 설계 전체 **FF 37,400개**다. FPGA 전체 가용 FF에 대한 사용률은 별도로 8.12%(37,400/460,800)다. FPGA 자원을 물리 면적 하나로 환산한 값은 아니다.

| 구역 | RTL 계층의 집계 대상 | FF | 전체 FF 비중 | LUT 참고 |
|---|---|---:|---:|---:|
| 전달 데이터 저장부 | 채널별 payload 하위 모듈 | **16,772** | **44.84%** | 4,242 |
| 샘플 연산부 | Loop_LOOP_T_proc_U0 전체 | **10,691** | **28.59%** | 23,410 |
| 진입부 | Block_entry_split_proc_U0 전체 | **9,201** | **24.60%** | 4,212 |
| 최상위 자체 로직 | (inst), 하위 모듈 제외 | 600 | 1.60% | 0 |
| 공유 FIFO 제어부 | fifo_shared_*_control 19개 | **136** | **0.36%** | 612 |
| **전체** | 위 다섯 구역의 합 | **37,400** | **100%** | **32,442** |

표의 비중은 반올림하므로 개별 표시값의 합이 정확히 100.00%가 아닐 수 있다. DSP 355개는 모두 샘플 연산부에 있고 BRAM은 0개다. 전체 LUT 32,442개에는 SRL 4,872개가 포함된다. SRL과 DSP 내부 레지스터는 이 FF 비중에 별도로 더하지 않는다.

### v3.5 대비 어디에서 FF가 줄었는가

| 같은 역할의 구역 | v3.5 FF | v3.6 FF | 변화 | 구역 자체의 변화율 |
|---|---:|---:|---:|---:|
| 전달 FIFO 전체 → payload + 공유 제어부 | 20,540 | 16,908 | **-3,632** | **-17.68%** |
| 샘플 연산부 | 10,967 | 10,691 | **-276** | **-2.52%** |
| 진입부 | 9,201 | 9,201 | 0 | 0.00% |
| 최상위 자체 로직 | 600 | 600 | 0 | 0.00% |
| **전체** | **41,308** | **37,400** | **-3,908** | **-9.46%** |

전체 FF 감소 중 **92.94%는 전달 구역**, 나머지 **7.06%는 연산부**에서 관측됐다. RTL 후처리로 구조가 달라진 뒤의 합성·물리 최적화 결과이므로 연산부 -276개까지 모두 삭제한 FIFO 제어 레지스터라고 해석하지 않는다.

### 전달 데이터 저장부의 추가 분류

| 생성 RTL 인스턴스 이름 기준 | routed payload 모듈 수 | FF | 전체 FF 비중 |
|---|---:|---:|---:|
| W_로 시작하는 가중치 전달 채널 | 225 | **6,300** | **16.84%** |
| 변환된 값 및 기타 채널 | 367 | **10,472** | **28.00%** |
| **payload 합계** | **592** | **16,772** | **44.84%** |

변환 대상으로 검사한 원래 채널은 598개지만 routed 보고서에 남은 payload 인스턴스는 592개다. 나머지는 합성 최적화 후 해당 계층 항목으로 남아 있지 않다. 원래 채널 수와 최종 물리 인스턴스 수를 같은 값으로 취급하지 않는다. 이 표는 이름에 따른 분류이며, 기타 10,472개를 모두 bias 또는 모두 가중치 복사라고 단정하지 않는다.

225개 가중치 채널은 각각 14비트·깊이 2이므로 FF 합계 225×14×2=6,300과 일치한다. 이 저장 공간은 현재 호출 간 파라미터 전달 의미를 유지하면서 남겨 둔 부분이다. 제어 공유만으로 가중치 저장 비트까지 제거되지는 않는다.

### 분석 한계와 다음 최적화의 우선순위

샘플 연산부 FF 10,691개 중 계층 자체에 10,689개, flow_control_loop_delay_pipe_U에 2개가 집계된다. 연산이 인라인되어 있으므로 현재 보고서만으로 FEx·각 GRU gate·hidden state·파이프라인 정렬용 FF를 정확히 나눌 수 없다. 진입부 9,201개와 최상위 600개도 세부 용도별 분해에는 RTL/netlist 레지스터 추적이 필요하다.

1. **전달 payload 16,772개:** 데이터의 유효 시점·수명과 동시 호출 수를 분석해 중복 저장이나 깊이 축소 가능성을 검토한다. II=2를 유지해도 FIFO stall이 늘 수 있으므로 호출 간격도 함께 검증한다.
2. **진입부 9,201개 및 연산부 10,691개:** 실제 레지스터 이름과 사용처를 추적해 변환값 저장·정렬 레지스터·상태 저장을 구분한다. 전체가 제거 가능한 중복이라는 가정은 하지 않는다.
3. **공유 제어부 136개:** 현재 전체 FF의 0.36%뿐이다. 이를 전부 없앤다고 가정해도 FF 1% 감소 기준 374개에 못 미친다. 기존 v3.5 대비 목표였던 414개도 달성할 수 없으므로 추가 FF 감소의 주 대상으로 삼지 않는다.

여기서 374개는 현재 v3.6의 FF 37,400개를 기준으로 한 1%이고, 414개는 앞선 실험에서 v3.5를 기준으로 정한 값이다. 이 분석은 후속 후보를 제시하는 것이며 새 합성이나 시뮬레이션을 실행한 결과는 아니다.

## 해석과 채택 판정

이번 자원 목표는 부모 대비 FF 1% 이상, 즉 최소 414개 감소였다. 실제 FF는 3,908개 감소했고 LUT도 4,869개 감소했다. DSP·BRAM 증가 없이 II=2, 실제 setup/hold 및 배선 조건을 통과하여 현재 자동 평가 기준에서 채택됐다.

제어부 개수가 598개에서 19개로 줄었다고 FIFO 전체 저장 용량이 같은 비율로 줄어든 것은 아니다. payload 저장부를 유지한 상태에서 중복 상태·제어망이 줄었고, 그에 따른 합성 및 배치배선 변화까지 포함한 **전체 설계의 순감소량**이 위 자원 차이다. 감소한 FF 3,908개를 모두 특정 제어 레지스터에 일대일 대응시킨 분석은 수행하지 않았다.

동시에 평가한 8개 공유 후보보다 32개 공유 후보가 LUT·FF를 적게 사용하여 사용자가 이 결과를 선택했다. 기존 8개 공유 후보는 삭제했고, 원래 v3.7로 실행한 32개 공유 결과를 현재 v3.6으로 번호 변경했다. 원본 도구 로그에 남은 v3.7 경로는 당시 실행 이력이며 별도의 현재 버전이 아니다.

15 ns 제약의 setup 여유는 0.027 ns다. 더 높은 주파수의 동작이나 모든 입력에서의 모델 정확도·전력 개선을 주장하지 않는다.

### 추가로 확인할 검증 범위

현재 PASS는 제공된 입력과 가중치의 7,680샘플 검증에 대한 결과다. 비중첩 호출 사이의 가중치 변경, 다양한 호출 간격·reset 순서 및 backpressure 조합에 대한 추가 회귀 검증은 아직 수행하지 않았다. C 검증과 구조 검사만으로 모든 조건의 RTL 동등성을 증명했다고 해석하지 않는다.
