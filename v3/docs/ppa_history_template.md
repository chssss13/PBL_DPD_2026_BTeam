# PPA 이력표

모든 변경은 **한 번에 하나**, 한 행에 기록합니다. "기능검증"과 "정확도"가 비어 있는 행은 무효입니다.

- 기능검증: `compare_out.py` 결과 (참조 대비 NMSE, PASS/FAIL)
- 정확도: `eval_pa.py` 결과 (PA 통과 NMSE / ACPR L / ACPR R)
- 처리율 = Fmax / II (MSps). Fmax는 구현 후 값 (`export_impl.rpt`의 Post-Route)
- **기준은 v1.1 (첫 기능·정확도 검증 통과 버전)** 입니다. # 열에는 버전명을 기록합니다. 개선률은 기준 버전 대비로 계산하며, 미측정 항목의 개선률은 산출하지 않습니다.
- **모든 HW 수치는 팀이 정한 하나의 측정 환경에서** 잽니다 (Windows PC 또는 Linux PC·서버). v0 행도 그 환경에서 다시 구현한 값으로 채우세요 (아래 v0 값은 조교 환경 참고값).

측정 주석: v0 행은 조교 참고값이 아닌 팀 Windows PC의 실제 구현 값으로 채웠다. 도구는 Vitis HLS/Vivado 2024.1, FPGA는 xczu7ev-ffvc1156-2-e, 목표 클록은 15 ns다. CPU·메모리는 미확인이다. v0 HLS uncertainty는 4.05 ns, 후속 버전은 1 ns로 합성 제약이 다르다. 처리율은 호출 오버헤드를 제외한 정상상태 환산값이며 보드 실측·전력은 미측정이다. 미측정은 —로 표시한다. 기능검증 PASS와 PA 정확도·II·timing 통과는 각각 구분한다.

v1.1은 C 기능·PA 정확도 검증을 통과했지만 실제 구현은 미측정이므로 이 행을 기준으로 물리 PPA 개선률을 계산하지 않는다. v1.6은 스케줄 조정·합성·RTL 검증, v1.7은 해당 합성 결과의 배치배선·PPA 측정으로 각각 별도 행에 기록한다. v1.7에 기재한 기능·PA 수치는 v1.6의 검증 결과를 계승한 것이며 신규 RTL 재평가를 뜻하지 않는다.

v3 기준은 우리 v2.2와 동일한 회로가 아니라 sehyeon v2 final에서 도입했다. v3.1의 부모는 v3 기준, v3.2의 부모는 v3.1이다. 표의 참조 NMSE −3028.13 dB는 불일치 0일 때 비교 스크립트의 수치 하한이며 PA 정확도가 아니다. v3.1은 정확도 개선, v3.2는 자원 개선으로 채택했다. 상세와 부모·원본 대비 변화는 [v3.1 결과](../results/v3.1/RESULTS.md)와 [v3.2 결과](../results/v3.2/RESULTS.md)에 기록한다. 미완료 후보는 이 표에 포함하지 않는다.
