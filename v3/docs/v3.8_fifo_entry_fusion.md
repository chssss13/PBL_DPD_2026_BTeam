# v3.8: 진입부 출력 보관과 FIFO 저장 경계 통합 실험

2026-11-16. 부모는 accepted v3.7이다. 전체 flow를 완료했고 판정은 **accepted**다.

## 문제와 후보

진입부 `Block_entry_split_proc_U0`는 terminal state4에서 계산 결과를 출력하고,
동시에 598개 `ap_return_*_preg` 출력 보관 레지스터에도 저장한다. 이후 top의
depth-one FIFO가 그 결과를 보관한다. FIFO가 가득 찬 경우 두 저장소는 서로 다른
호출 값을 담을 수 있으므로, 같은 값이 관측된다는 이유로 단순 삭제할 수 없다.

v3.8 후보는 진입부가 `ap_continue`를 받기 전까지 state4에 머무르게 하고,
`ap_ready`도 `ap_continue`가 있을 때만 올린다. 대기 중에는 새 입력 호출을
수락하지 않고 terminal 계산 결과를 유지해 별도의 출력 보관 레지스터를 없앤다.
FIFO의 깊이 1과 32개 단위 공유 제어, 데이터 폭, C++ 수식은 v3.7 그대로다.
변경한 진입부 RTL은 top에 포함해 export 후 구현에도 같은 모듈을 사용한다.

이는 자체 RTL 실험이며 기존 회로와 모든 클럭에서 같다는 주장은 하지 않는다.
대기 처리와 입력의 유효 기간이 달라지므로 통합 handshake 검증이 필요하다.

## 검증

- 실제 부모/후보 진입부의 598개 출력을 비교했다. 호출별 입력 변경 250회,
  임의 terminal 대기 2,896클록, 대기 중 reset을 포함해 3,131회 비교를 통과했다.
  RAM은 각 모듈의 주소·CE에 따라 1클록 뒤 값을 반환하는 동기 모델을 사용했다.
  이 단위 검증은 전체 네트워크 검증을 대신하지 않는다.
- 7,680샘플 C/독립 정수 참조/수정 RTL 일치, PA 기준과 부모 출력 일치를 확인한다.
- II=2 및 부모 대비 호출 간격/전체 실행 시간 증가 없음을 확인한다.
- 검증한 RTL로 15 ns setup/hold와 배선 오류 0을 확인한다.
- 부모 대비 FF 1% 이상 절감, 다른 자원 1% 초과 증가 없음, BRAM 신규 사용 없음을
  기존 flow 기준으로 판정한다.

부모 소스와 결과는 보존한다. 현재 문서에는 측정 전 예상 절감량을 실측처럼 쓰지 않는다.

## 완료한 검증과 남은 판정

기본 7,680샘플 C/독립 참조/수정 RTL 비교는 통과했다. PA 지표는 부모와 같고,
LOOP_T II=2, RTL 호출 지연 145클록, 호출 간격 134클록, 전체 실행 16,091클록으로
부모와 같다. 배치배선의 15 ns setup/hold와 배선 검증도 통과했다.

| 항목 | v3.7 | v3.8 | 변화 |
|---|---:|---:|---:|
| FF | 28,978 | 20,804 | -8,174 (-28.21%) |
| LUT | 27,127 | 22,893 | -4,234 (-15.61%) |
| DSP | 355 | 355 | 0 |
| BRAM_18K | 0 | 0 | 0 |
| 구현 비교 주기(ns) | 14.907 | 14.941 | +0.034 |

WNS +0.059 ns, WHS +0.029 ns, routing errors 0, unrouted nets 0이다.
출력 보관 제거에 따른 전체 물리 구현의 순절감이며, 줄어든 FF 모두를 특정
레지스터에 직접 귀속시키는 집계는 아니다. [최종 결과](../results/v3.8/RESULTS.md)와
[판정 상태](../results/v3.8/state.json)에 근거를 보관했다.

별도 합성 DB 복사본에서 모든 가중치·bias 계열을 호출마다 바꾸고 hidden state
초기화 호출을 0, 7, 11, 14, 21, 22로 바꾼 추가 회귀도 통과했다. 24회 호출,
1,536샘플에서 C/RTL Q12 불일치 0개, 호출 지연 145클록, 간격 134클록이다.
이 회귀 RTL 해시는 기본 구현에 설치한 RTL 해시와 같다. 결과는
`results/v3.8/weight_call_regression/summary.json`에 보관했다. 변경된 가중치에 대한
PA 품질 평가나 임의 외부 backpressure·전체 시스템 reset 검증을 뜻하지는 않는다.

최초 전체 RTL 실행 전 변환 스크립트의 인스턴스 공백 검사 오류를 수정했다.
C++나 합성 스케줄을 바꾼 수정은 아니며 완료된 C/HLS 결과를 재사용했다.
수정 전후 해시와 오류는 `results/v3.8/integration_repair.json`에 기록했다.
