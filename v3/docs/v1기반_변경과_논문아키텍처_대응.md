# v1 기반 채택 변경과 논문 아키텍처의 대응

작성: 2026-11-03. 구성 정리: 2026-11-04. [시간순 채택 변경 이력](v1기반_채택변경_이력.md)의 1~15번을 대상으로 한다. 최종 소스는 [state_nosat 실험 스냅샷](../src/), 최종 선정·검증 조건은 [decision.json](../reports/결과요약.md)을 기준으로 한다.

논문: Daegyeom Kim, Sehoon Park, Sunmean Kim, *LW-ResGRU DPD: Layer-Wise Residual GRU for Low-Latency DPD in Nonlinear RF Systems*, IEEE TCAS-II 73(2), pp.153–157, 2026. DOI: 10.1109/TCSII.2025.3640703. [논문 DOI](https://doi.org/10.1109/TCSII.2025.3640703). 아래 페이지는 인쇄 쪽수이며, PDF 1~5쪽에 각각 153~157쪽이 대응한다.

**전체 모델의 블록 구성과 레이어별 잔차 연결을 유지하면서, 주로 GRU 내부의 수치 표현·연산 배치·자원 공유를 수정했다.** 논문에 설명된 원리와 일치하는 부분도 있지만, 모든 변경이 논문에서 제안된 기법은 아니다. 논문의 설명, 코드에서 확인한 대응, 우리 실험·범위 분석의 근거를 구분한다.

## 1. 논문의 그림에서 어느 부분인가

그림 2(b)(p.154)는 모델 구성, 그림 4(p.157)는 HLS 하드웨어 구성을 보여준다. 식 (1)~(4)는 FEx, 입력 투영, 레이어별 잔차, 출력 투영에 해당한다.

```text
I/Q → FEx → 입력 FC → PReLU → [ResGRU × 3] → 출력 FC → I/Q
       ④      ②⑤⑨          ┌──────────────────────────┐
                            │ MVM: 입력곱 + recurrent곱 │ ← ⑩⑪⑫⑬
                            │ Gate: sigmoid / tanh     │ ← ③⑧⑨
                            │ Gate: 은닉 상태 갱신      │ ← ⑦⑭⑮
                            │ H MEM: 이전 상태 저장     │ ← ①
                            │ 잔차: h + σ(S)·층 입력    │ 구조 유지
                            └──────────────────────────┘
②⑤⑨의 공통 자료형 변경은 여러 블록에 걸친다. ⑥은 HLS 스케줄 설정이다.
```

| 논문 위치 | 역할 | 최종 코드의 대응 |
|---|---|---|
| II-A-1, 식 (1), 그림 4의 FEx | I/Q에서 진폭·진폭 세제곱·위상 성분 추출 | `linear_layer.h::FExLayer` |
| II-A-2, 식 (2), 입력 FC | 6개 특성을 H=5 차원으로 투영 | `ResGRU`의 `IN_INJECT`, `Linear<6,H_SIZE,...>` |
| II-A-3, PReLU | 투영 결과의 음수 구간에 학습한 기울기 적용 | `ResGRU`의 `PReLU`, `nnet::prelu` |
| II-A-4, 그림 4 ResGRU 안의 MVM | 현재 층 입력과 이전 은닉 상태의 가중 행렬곱 | `gru_cell.h::GRU_Kernel_PE`의 입력 3개·recurrent 3개 MVM 호출 |
| 같은 그림의 Gate | r/z 게이트, 후보 상태 n, 최종 은닉 상태 계산 | `gru_cell.h::Gate_Calc_PE` |
| 같은 그림의 H MEM | 시간 방향으로 이전 은닉 상태 유지 | `ResGRU`의 `h_state_all`, `GRU_single`의 reset 선택 |
| 식 (3), ResGRU 바깥 덧셈·잔차 경로 | 각 층 입력을 가중해 GRU 출력에 더함 | `ResGRU`의 `RES_J`: `layer_out[l] + gating_params[l]*layer_in[l]` |
| II-A-5, 식 (4), 출력 FC | 마지막 층 출력을 I/Q 두 값으로 투영 | `ResGRU`의 `OUT`, `Linear<H_SIZE,2,...>` |


코드에는 이전 구현의 보조 함수와 주석도 남아 있다. 이 대응은 합성 top인 `ResGRU`에서 실제 호출하는 경로를 따른다. 특히 잔차 부분의 주석은 `persistent x0`라고 남아 있지만, 실행되는 식의 입력은 `layer_in[l]`이다. 이는 식 (3)의 이전 층 출력/현재 층 입력에 대응한다. 테스트벤치가 읽는 `gating`에는 이미 sigmoid가 적용되어 있다([tb_resgru.cpp](../tb/tb_resgru.cpp)). 따라서 이 잔차 계수와 GRU 내부의 매 샘플 z 게이트를 혼동하면 안 된다.

## 3. 최근 변경을 GRU 수식에 연결하면

논문은 II-A-4에서 GRU 내부를 표준 GRU로 설명하고 참고문헌 [10]을 인용한다. 아래 식은 **현재 C++를 풀어 쓴 위치 안내**이며, 논문에 번호가 붙어 실린 식을 옮긴 것이 아니다. 편의를 위해 한 층의 현재 입력을 x, 이전 상태를 h, 후보 상태를 n으로 쓴다. 실제 코드에는 대입·곱·누산별 양자화가 있다.

```text
r = sigmoid(W_ir·x + b_ir + W_hr·h + b_hr)
z = sigmoid(W_iz·x + b_iz + W_hz·h + b_hz)
n = tanh(W_in·x + b_in + r ⊙ (W_hn·h + b_hn))
h_next = n + z ⊙ (h - n)
```

- **10·12·13번:** `W_hr·h`, `W_hz·h`, `W_hn·h`를 계산하는 곱셈 인스턴스의 구분을 바꾼다. 13번은 그중 `W_hn·h`에 한정된다.
- **11번:** 위 식의 여섯 MVM에서 각 행의 5개 곱을 더하는 중간 자료형을 바꾼다. 입력/출력 FC는 이 누산 확대 대상에서 제외했다.
- **9번의 보간:** 위 식의 sigmoid 두 호출과 tanh 호출 안을 바꾼다. 입력 FC 뒤의 PReLU를 보간으로 바꾸는 작업이 아니다.
- **14·15번:** 마지막 `h_next` 식의 z 입력 표현과 결과 저장 변환을 바꾼다. `r ⊙ (W_hn·h+b_hn)`의 포화를 제거한 것이 아니다.

그 뒤 실행되는 레이어별 잔차는 별도 식이다.

```text
층 출력 = h_next + gating_params[l] × 층 입력
```

이것이 논문 식 (3)에 해당한다. 시간 방향으로 저장하는 값은 `h_next`이고, 다음 층으로 전달하는 값은 잔차를 더한 층 출력이다. **15번의 범위 증명은 잔차를 더하기 전 은닉 상태에 적용한다.** 잔차 합까지 같은 범위라고 증명한 것은 아니다.

## 4. 근거가 특히 명확한 세 가지

### 256구간 선형 보간: 논문 원리 + 자체 수치 선택

논문 III-B-1(p.156)은 sigmoid/tanh를 구간별 선형 근사로 구현한다고 명시한다. 현재 구현은 구간 시작값 B와 끝점 차이 D를 저장하고 구간 안의 위치 f로 `B + D·f`를 계산한다. 이 구현이 해당 원리와 대응한다.

다만 논문에는 256구간, [-4,4) 범위, Q12 표, packed B/D, fabric 곱셈 등의 구체값이 제시되어 있지 않다. 이 부분은 우리의 선택이다. 코드의 `config_a::table_size=4096` 선언만으로 현재 구간 수를 판단하지 않고, 실제 `sigmoid_comb`/`tanh_comb`가 읽는 256항 표를 기준으로 확인했다.


### 곱셈 분리: 논문의 PE 개념 + 자체 공유 회로 분석

논문은 FC/GRU MVM을 PE로 병렬화한다고 설명한다. 우리 수정은 그 MVM을 구현할 때 HLS가 어떤 호출끼리 연산기를 공유할 수 있는지를 함수 특수화로 제한하는 방식이다. `GATE`, `TERM`, `ROW`는 모델에 새 차원을 추가하는 값이 아니라 같은 모델 연산을 하드웨어에서 구분하기 위한 값이다.

분리로 DSP가 늘 수 있지만, 동시에 선택 회로·연결·배치가 달라진다. 실제로 누산 wide→항별 분리는 DSP333→337, LUT42,163→41,735, 비교 주기17.310→16.427ns였다. n 행별 분리에서는 DSP347, 비교 주기15.266ns가 됐다. 반면 이후 r/z 레이어 분리나 z 행별 분리 실험은 채택하지 않았다. 따라서 “병렬화를 늘리면 언제나 빨라진다”는 근거로 쓰지 않는다.


### z 폭 축소·상태 포화 생략: 범위에 근거한 자체 최적화

현재 sigmoid의 입력 코드 32,768개를 확인한 결과 z의 Q12 raw 값은 74~4,022다. unsigned12의 0~4,095 안에 들어가므로 하위 12비트만 선택해도 값이 달라지지 않았다. 이는 이상적인 sigmoid의 성질만 가정한 것이 아니라 실제 표와 코드 형식에 대한 검사다.

상태식은 `h_next=(1-z)n+z·h_prev`로 쓸 수 있다. 0≤z<1이면 두 계수는 음수가 아니며 합이 1이다. 따라서 정확한 중간 연산 결과는 두 입력 사이에 있고, 같은 Q12 형식으로 반올림해도 표현 범위를 넘지 않는다. 4,096개 z 코드와 n/h 양 끝값의 네 조합, 총 16,384개 경계 결과를 검사했다. 고정한 z에서 식이 n/h에 대해 단조이므로 내부 값의 범위도 이 경계로 제한된다.

이 근거는 식의 중간 정밀도를 유지하는 현재 C++에 적용한다. 중간 값을 먼저 좁히거나 활성화 표·입력 형식을 바꾸면 다시 검토해야 한다. 특히 11번 누산 wide는 원래 매 항 포화하던 연산과 모든 입력에서 항상 같다는 증명이 아니며, 15번의 범위 증명과 구분한다.


## 5. 대응을 과장하지 않기 위한 구분

- **논문의 핵심 모델 구조:** H=5, L=3, FEx→입력 FC→PReLU→층별 잔차 GRU→출력 FC 구성을 유지한다. 최근 변경으로 새로운 잔차 연결을 만들거나 GRU의 레이어 수·은닉 크기를 바꾼 것은 아니다.
- **그림 4의 parameter BRAM:** 논문의 매개변수 메모리 표현이다. 우리 최종 P&R의 BRAM은 0이다. 따라서 전체 메모리 배치까지 그림 4와 같다고 쓰지 않는다. BRAM 제거를 이번 1~15번 중 새로운 채택 변경으로 소급해 만들지도 않는다.
- **시간 방향 의존성:** H MEM에 저장된 이전 상태를 사용하는 의존성은 유지된다. 곱셈기 분리로 공유 회로를 줄이는 것과 GRU의 실제 시간 의존성을 없애는 것은 별개다.
- **타이밍 근거:** 마지막 후보의 최악 경로는 공유 tanh→상태 갱신→bypass→공유 r recurrent MVM→r_pre 포화 판정으로 이어진다. 자원을 공유하는 물리 연결이므로 한 샘플의 수식 순서라고 단정하지 않는다. 최종 RTL·경로 분석.
- **논문 수치와 비교:** 표 III는 Vivado 2024.1의 배치·배선 후 자원 표이고, 본문은 66MHz 조건을 명시한다. 우리 15ns 제약의 WNS와 같은 수치라고 놓거나, 논문의 II=2를 우리 최종 P&R 통과의 증거로 사용하지 않는다.

현재 채택본의 직접 검증은 C-sim 7,680개 Q12 일치, HLS II=2, IP 내부 15ns 제약에서 P&R WNS +0.093ns와 setup/hold 위반 0개다. 2026-11-05 별도 재합성한 최종 RTL의 co-sim도 7,680개 PASS했다. 외부 I/O 통합 타이밍·보드 실측은 별도다. 이 문서는 논문과 코드의 대응 및 수정 근거를 정리한 기록이다. 재현 보관본의 재현 확인 범위는 최상위 README에 기록했다.
