# v3.7: 전달 FIFO 데이터 저장 깊이 축소 실험

2026-11-15. 부모는 v3.6이다. 전체 flow가 완료됐으며 현재 검증 기준에서 채택됐다. 추가 동작 조건 검증은 남아 있다.

## 목적과 변경

v3.6의 전달 payload가 전체 FF의 44.84%(16,772개)를 차지한다. 32개 단위 제어 공유와 DATAFLOW를 유지하면서 598개 채널의 저장 깊이를 2에서 1로 줄이는 후보를 평가한다. 데이터 폭과 C++ 연산식은 그대로다. full/empty와 fifo_cap도 용량 1에 맞춰 함께 바꾼다.

이는 단순 제어 공유와 달리 저장 가능한 호출 수와 backpressure를 바꿀 수 있다. 임의의 중첩 호출에서 기존 회로와 매 클럭 동일한 동작이라고 가정하지 않는다. 외부 포트 형식은 유지하되 기존 검증의 호출 간격이나 전체 실행 시간이 늘어나면 채택하지 않는다.

## 근거

[FIFOAdvisor, ASP-DAC 2026](https://arxiv.org/html/2510.20981v1)의 시뮬레이션 기반 FIFO 용량 탐색 방향을 참고한다. 해당 탐색기나 BRAM 목적 함수를 재현한 것이 아니라, 현재 얕은 scalar FIFO에서 용량 1이 충분한지 검증하는 자체 후보다.

## 검증 순서

1. 실제 제어 RTL과 HLS payload 모듈을 연결해 20,000클럭의 임의 데이터·읽기/쓰기 대기·동시 요청·reset 단위 검증을 수행한다. 이 단위 검증은 전체 네트워크의 무교착 증명을 대신하지 않는다.
2. 전체 7,680샘플 C/독립 정수 참조/수정 RTL을 비교하고 PA 기준을 확인한다.
3. LOOP_T II=2, RTL 호출 간격 134클럭 이하 및 전체 실행 16,091클럭 이하를 확인한다.
4. 검증한 RTL을 IP에 설치하고 실제 15 ns setup/hold·배선 오류 0을 확인한다.
5. 부모 대비 FF 1% 이상(374개 이상) 감소, 다른 자원 증가 1% 이하, BRAM 신규 사용 없음을 확인한다.

미달이면 원인을 공통 로그에 기록하고 후보 소스·결과·상세 문서를 삭제한다. 도구 연결 오류는 개선 기법의 탈락으로 처리하지 않고 수정 후 재개한다. 가중치 변경과 추가 호출/reset 패턴은 기본 벡터 검증과 구분하여 보고한다.

비중의 분모는 설계 FF 28,978개다. FPGA 가용 FF 460,800개 대비 사용률은 별도로 6.29%다. 전체 LUT에는 logic LUT 22,254개와 SRL 4,873개가 포함되며 SRL을 FF에 더하지 않는다. DSP 355개는 모두 연산부에 있고 BRAM은 0개다.

### v3.6 대비 FF 감소 위치

| 구역 | v3.6 FF | v3.7 FF | 변화 |
|---|---:|---:|---:|
| 전달 데이터 저장부 | 16,772 | 8,386 | **-8,386 (-50.00%)** |
| 공유 제어부 | 136 | 38 | **-98** |
| 샘플 연산부 | 10,691 | 10,753 | **+62** |
| 진입부 | 9,201 | 9,201 | 0 |
| 최상위 자체 로직 | 600 | 600 | 0 |
| **전체** | **37,400** | **28,978** | **-8,422 (-22.52%)** |

payload 저장부의 물리 FF는 정확히 절반으로 줄었다. 전달 구역 전체는 16,908→8,424개(-8,484개)이고 연산부에서 62개 늘어 최종 순감소가 8,422개다. 용량 변경이 합성·물리 최적화에도 영향을 주므로 순감소량 전체를 payload만의 효과로 기술하지 않는다.

LUT 변화는 payload -4,242개, 제어부 -92개, 연산부 -1,010개, 진입부 -3개로 합계 -5,315개다. 깊이 1 payload는 routed 계층에서 LUT 0개·FF 8,386개로 구현됐다.

### 전달 데이터 저장부의 구성

| 인스턴스 이름 기준 분류 | routed payload 모듈 수 | FF | 전체 FF 비중 |
|---|---:|---:|---:|
| W_로 시작하는 가중치 채널 | 225 | **3,150** | **10.87%** |
| 변환된 값 및 기타 채널 | 367 | **5,236** | **18.07%** |
| **payload 전체** | **592** | **8,386** | **28.94%** |

가중치 채널은 225×14비트×깊이 1=3,150 FF로 집계된다. 대상 원래 채널은 598개지만 합성 최적화 후 계층 보고서에 남은 payload는 592개다. 기타 5,236개는 이름에 따른 분류이므로 모두 bias나 모두 중복 가중치 저장이라고 간주하지 않는다.

### 중복 저장 분석과의 관계

현재까지 적용한 것은 제어 공유와 저장 깊이 축소다. 이 표는 불필요한 중복 저장의 존재를 증명한 결과가 아니다. 서로 같은 값이 들어 있어도 다른 호출이나 파이프라인 단계의 값을 보존하는 레지스터일 수 있다.

이제 연산부와 진입부가 합계 **19,954 FF(68.86%)**를 차지한다. 다음 우선 분석 대상은 진입부 9,201개의 출력·중간값 레지스터와 소비자 저장의 수명 관계다. 가중치가 바뀌는 호출까지 고려해 중복인지 판단해야 한다.

연산부 FF 10,753개는 자체 계층 10,694개, flow-control 2개, 곱셈 하위 모듈 3개 각 19개로 집계된다. 인라인된 FEx·GRU gate별 세부 용도는 현재 계층 보고서만으로 분리되지 않는다. 제어부는 38 FF뿐이므로 이를 전부 제거해도 현재 FF 1%인 290개에 못 미친다.

이 집계는 추가 합성 없이 기존 routed 보고서를 분석한 것이다.
