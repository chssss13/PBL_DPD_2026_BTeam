# C21 NR2 배선 후 최악 경로 분석

2026-11-06. 원본 `timing100/setup_paths100.rpt`의 최대 setup 경로 100개와 동일 C21의 HLS RTL/스케줄을 읽었다. 기준은 `v2/package/results/v1_gru_accum_wide_z_unsigned12_state_nosat_csynth`의 NR4 결과. 합성이나 소스 변경은 하지 않았다.

## 결론과 비교

C21 최악 경로는 NR을 지나지 않는다. tanh 입력 레지스터→tanh 보간→상태 갱신→상태 선택→공유 recurrent 곱셈→반올림/포화 관련 판단 레지스터에 이르는 GRU 경로다. HLS RTL상 상태 직접 전달과 저장 상태 사이 선택, 서로 다른 recurrent 곱셈 입력 선택이 함께 존재한다. 이는 실제 데이터 의존과 공유·선택 구조가 공존한다는 뜻이며, 모든 선택 조합이 동작상 동시에 활성화될 수 있는지 이 분석만으로 증명한 것은 아니다.

| | 최종 v2 NR4 | C21 NR2 |
|---|---:|---:|
| WNS | +0.093 ns | −0.474 ns |
| 비교주기 15−WNS | 14.907 ns | 15.474 ns |
| 최악 데이터 경로 | 14.888 ns | 15.455 ns |
| 논리 지연 | 7.851 ns | 7.971 ns |
| 배선 지연 | 7.037 ns | 7.484 ns |

최악 경로 지연의 차이 +0.567ns 중 논리 +0.120ns, 배선 +0.447ns. **서로 다른 시작점과 개별 경로 비교**이므로 이것만으로 동일 회로의 배선이 0.447ns 늘었다거나 NR 변경의 단독 물리 원인을 특정할 수 없다. HLS 추정 주기는 동일13.881ns이나 P&R 구조·배치·배선은 다를 수 있다.

100경로에서 C21은 전부 `am_submul` 관련 셀 및 `Recurrent_Term_Product` 관련 셀을 지나며 NR `mul_42s`/`mul_57s` 이름은 없다. 기준도100개 전부 `am_submul`,94개가 `Recurrent_Term_Product`를 지난다. 구현 최적화로 셀 명칭과 재매핑이 있을 수 있으므로 문자열 집계는 경향이며 C21의 모든 경로가 동일 연산 순서라는 뜻은 아니다.

C21 시작점은 tanh 입력 레지스터 `select_ln220_3_reg_155416` 비트군 51개, `select_ln220_7` 10개, 다른 tanh 입력 그룹8개, `ap_enable_reg_pp0_iter7` 제어31개다. 서로 다른 endpoint를 대상으로 한 최악100개이며 전체 가능한 경로의 통계는 아니다.

## 최악 경로의 RTL 추적

경로 출발점 `select_ln220_3_reg_155416[12]/C`, 도착점 `and_ln223_57_reg_155731[0]/D`. 같은 RTL `prj/sol1/syn/verilog/ResGRU_Loop_LOOP_T_proc.v`에서:

1. 31505행 레지스터가 `select_ln220_3_fu_65163_p3`을 저장한다. 이 신호는 스케줄 ST8의 gru_cell.h220 `n_pre` 선택 결과이고, 39714행에서 tanh 입력으로 연결된다. ST9에서 tanh 결과 `n`이 나온다.
2. 31086행 부근 U814의 din1은 해당 tanh 출력, din0은 저장된 이전 상태 선택값, din2는 z값. 출력 `grp_fu_151652_p3`는 74268행에서 상태 갱신식의 일부로 연결된다. ST9의 `add_ln232`와 `h_rounded_fu_67161_p2`는 gru_cell.h232의 `n + z*(h_prev-n)`에 해당한다.
3. 34542행은 `h_rounded`를 저장하고, 34670~34672행 mux는 **새 `h_rounded`와 기존 상태 레지스터**를 선택한다. 61750행 reset 조건 선택 `select_ln35`가 35890행의 `Recurrent_Term_Product_1_0` x 입력 선택으로 연결된다. 해당 연산기의 w 입력 역시 서로 다른 저장 가중치를 선택한다(35878~35880행). 따라서 레지스터 입력과 별도로 새로운 상태를 직접 선택할 수 있는 조합 경로가 있다.
4. report의 첫 DSP는 최적화 후 `add_ln232_fu_67134_p2`, 두 번째는 `Recurrent_Term_Product_1_0/.../U534`의 DSP 입력 A→곱→출력을 거친다. 중간 `U819` 이름을 가진 LUT를 통과하지만 그것만으로 U819 곱셈 전체를 통과한다고 해석하지 않는다. 동일 연산기 출력은 슬라이스·반올림/포화 판단 논리와 다음 연산에 사용된다.
5. 스케줄 ST10의 `and_ln223_57`은 gru_cell.h223의 `z_pre` 변환에 관련된 판단 비트로 매핑되며, 31475행에서 도착 레지스터에 저장된다. `and_ln223_57`은 부호/포화 판단 논리의 일부이며, 이 한 비트만으로 전체 z값을 의미하지 않는다.

최종 v2의 최악 경로도 상태 갱신 곱셈과 recurrent 곱셈을 함께 지난다. 다만 기준 시작점은 FSM 제어 레지스터이며 C21은 tanh 입력 레지스터라 정확히 동일 비트 경로는 아니다. NR2 변경이 이 GRU 경로의 원래 C++ 식을 바꾼 것은 아니다. 새 스케줄/RTL/물리 최적화 전반이 결과에 영향을 줄 수 있으며 어느 한 요소의 기여도는 분리하지 않았다.

## 판단

NR2는 이 실행에서 LUT−490/DSP−7/FF+425였고 WNS−0.474ns. 이 상태에서15ns 조건에는 미달한다. NR3도 같은 경로/결과일지는 별도 P&R 전 알 수 없다. 사용자 판단 전 채택·기각은 확정하지 않는다.
