# v3 미채택 실험 요약

2026-11-07 기준. csynth 또는 Vivado P&R까지 실행한 후보를 대상으로, 변경 내용과 미채택 이유를 짧게 정리했다. 현재 채택본은 [v3.3](v3.3/README.md)다. **명시적으로 기각한 후보, 목표 미달 후보, 판단을 보류한 후보를 구분한다.**

대부분의 기준은 [v2 최종본](../../v2/result/final/README.md)이다. 기준 P&R은 LUT 41,387 / FF 41,088 / DSP 362 / BRAM 0, 15ns 제약에서 WNS +0.093ns다. 아래 자원 증감은 별도 표시가 없으면 v2 대비이며, HLS 추정치와 P&R 결과를 섞어 비교하지 않았다.

## 기각하거나 목표를 충족하지 못한 후보

| 후보 | 시도한 변경 | 확인 결과와 미채택 이유 |
|---|---|---|
| [C01](c01_sigmoid_bram/README.md) | sigmoid 보간표를 BRAM으로 구현 | **P&R 목표 미달.** LUT는 1,338개 감소했으나 DSP는 31개 증가하고 BRAM18K 15개 사용. WNS −0.851ns로 15ns 타이밍 실패. |
| [C03](c03_r_unsigned12/README.md) | r을 signed 15/3 → unsigned 12/0으로 축소 | **기존 v2 유지 결정.** P&R LUT는 90개만 감소하고 FF는 68개 증가. WNS +0.052ns로 통과했지만 기존보다 여유가 줄어 채택하지 않음. |
| [C04](../package/results/final_recurrent_acc19_csynth/README.md) | recurrent 누산 폭 21/6 → 19/4 | **기각.** P&R LUT +3,212개, FF +151개로 오히려 증가. WNS −0.423ns로 타이밍도 실패. |
| [C06](../package/results/final_no_top_dataflow_csynth/README.md) 및 아래 파생 후보 | 최상위 DATAFLOW 제거 후 II 회복 시도 | **HLS II 목표 미달.** 자원 추정치는 크게 줄었지만 아래 변경으로도 II=3을 벗어나지 못함. 이 조건들의 P&R은 미실시. |
| [C16](../package/results/c16_pnr_retry02/README.md) | DATAFLOW 제거·누산 포화 제거 상태에서 클럭을 18ns로 완화 | **해당 방향 미채택.** HLS에서는 II=2였으나 P&R WNS −79.116ns, 비교 주기 97.116ns. 최악 경로는 FEx NR 공유 곱셈기 연결에서 확인됨. 단순히 배선만 길어진 문제가 아니었음. |
| [C21](../package/results/final_nr2_csynth/README.md) | FEx NR 반복 4회 → 2회 | **P&R 목표 미달.** LUT −490개, DSP −7개지만 FF +425개. WNS −0.474ns로 타이밍 실패. |

DATAFLOW 제거 계열의 세부 시도는 다음과 같다. C07·C08·C10은 C06에서 각각 분기한 대안이며, 순서대로 누적한 변경이 아니다.

- [C07](../package/results/final_no_top_dataflow_tanh_layer_split_csynth/README.md): tanh 함수를 레이어별로 분리 → II=3.
- [C08](../package/results/final_no_top_dataflow_r_layer_split_csynth/README.md): r 관련 recurrent 곱셈을 레이어별로 분리 → II=3.
- [C10](../package/results/final_no_top_dataflow_state_scope_csim/README.md): 시간 루프·상태의 함수 경계 변경 → II=3.
- [C13](../package/results/final_recurrent_acc_nosat_no_top_dataflow_csynth/README.md): C12의 recurrent 누산 포화 제거에 DATAFLOW 제거를 결합 → II=3.
- [C14](../package/results/final_recurrent_acc_nosat_no_top_dataflow_unc0_csynth/README.md): C13에서 15ns 클럭, uncertainty 0ns → II=3.
- [C15](../package/results/final_recurrent_acc_nosat_no_top_dataflow_clk16_unc1_csynth/README.md): 같은 소스에 16ns 클럭, uncertainty 1ns → II=3. 18ns/1ns의 C16에서야 II=2였지만 P&R은 실패했다.

채택한 **C23 sigmoid 대칭성·V01/N1b AreaOptimized_high는 [v3.1](v3.1/README.md)**, **P08 recurrent 곱셈 직후 포화 제거는 [v3.2](v3.2/README.md)**에 기록했다. 이들은 기각 목록에 포함하지 않는다.

실행 준비 오류와 재시도는 설계 기각 이유와 구분했다. Python만 실행한 아이디어 및 완료 전 취소한 설정은 이 목록에서 제외했다. P&R 비교 주기는 `클럭 제약 − WNS`이며 데이터 경로 지연 자체와는 다르다. 전체 경과와 원본 근거는 [후보 통합 기록](README.md) 및 각 후보 링크를 참조한다.
