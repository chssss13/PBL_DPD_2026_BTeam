# C01 sigmoid BRAM P&R 경로 분석

2026-11-05. 기준은 첫 IP 생성 실패가 아닌 `final_sigmoid_bram_pnr_retry01`의 완료된 routed DCP와 `timing100` 보고서다. 현상·RTL 연결과 개선 가설을 구분한다. 합성이나 설계 변경은 수행하지 않았다.

## 최악 경로

- 15ns 제약, WNS −0.851ns, 데이터 경로 지연 15.564ns(논리 7.937ns, 배선 7.627ns), 53 논리 레벨. BRAM 주소 setup −0.263ns, 클록 스큐·uncertainty 때문에 `15−WNS = 15.851ns`와 데이터 경로 지연은 다르다.
- 시작점은 `ap_enable_reg_pp0_iter10_reg_replica_3`의 Q로, tanh 수치 레지스터가 아니라 파이프라인 제어 레지스터다. 끝점은 sigmoid 함수 `fu_6170`의 `packed_rom_U` RAMB18E2 주소 입력이다.
- 첫 경로에는 tanh 보간 조합 논리, 상태 갱신 DSP 관련 논리, `Recurrent_Term_Product_0_3`의 곱셈 DSP, 누산·반올림/선택 논리, sigmoid BRAM 주소가 순서대로 나타난다. 이는 레지스터 사이의 정적 타이밍 경로이지 신호 이름만으로 하나의 샘플이 순차 실행된다는 증거는 아니다.
- 경로 말미 BRAM 주소 setup 요구는 −0.263ns지만, 이 값 하나가 기준 대비 WNS 악화 −0.944ns의 전체 원인이라고 할 수 없다. 배치·배선, 스케줄, 공유와 다른 논리도 달라졌다.

## RTL에서 확인한 연결

1. `tanh_comb fu_6199` 입력은 상황에 따라 `select_ln220_55_reg_158484` 또는 `select_ln220_15_reg_157909`를 고르는 mux를 통과한다. 해당 제어는 파이프라인 유효 신호와 상태에 의존한다.
2. 그 tanh 출력은 상태식 연산 `am_submul ... U851`의 `din1`에 연결된다. `din0`은 `select_ln35_3_reg_157844`, `din2`는 12비트 `grp_fu_154224_p2`다. 따라서 tanh 출력과 상태 갱신 연산 연결은 RTL 포트로 확인된다.
3. `Recurrent_Term_Product_0_3 fu_5443`의 `x`는 두 단계에서 계산된 값 중 하나를 선택한다. 그 중 `select_ln35_13`은 0 또는 상태값 선택 신호를 전달하고, 상태값 선택은 새로 계산한 `h_rounded_13`과 저장된 이전 상태 중 하나를 고른다. `w`도 두 레지스터 값 중 선택한다. 즉 상태 갱신→recurrent 곱셈의 실제 데이터 연결과 구현상 공유 선택이 함께 존재한다.
4. sigmoid `fu_6170`의 `data` 역시 서로 다른 파이프라인 단계의 `select_ln216_59` 또는 `select_ln216_35`를 고르는 mux를 통과한다. `select_ln216_59`는 게이트 입력의 합과 고정소수점 범위 처리 관련 선택을 거친다. sigmoid 내부에서 부호 비트를 변환한 `data[14:7]`이 `packed_rom_address0`으로 연결된다. `fraction`은 별도 레지스터에 저장된다.
5. 따라서 endpoint는 **BRAM 읽기 결과 뒤의 보간 곱셈이 아니라 BRAM 주소 입력**이다. 상위 단계가 생성한 sigmoid 입력이 클록 에지 전에 도착해야 한다. 함수의 합성 보고서는 ROM latency 1, 함수 latency 1·interval 1로 기록한다.

## 상위 100경로

- 슬랙 −0.851~−0.638ns. 99개가 sigmoid BRAM 주소 입력에서 종료한다(ADDRARDADDR 51개, ADDRBWRADDR 48개). 나머지 1개는 일반 레지스터 D 입력이다.
- 시작점은 제어 레지스터 복제본 `iter10` 계열 75개, FSM 레지스터 복제본 18개, tanh 입력 관련 데이터 레지스터 7개다. 동일한 경로의 비트·복제본이 반복될 수 있으므로 100개의 독립 원인이라고 해석하지 않는다.
- 경로 문자열 기준 recurrent 곱셈 관련 계층 100개, 상태식 곱셈 관련 계층 100개, tanh 관련 계층 99개가 나타난다. 이는 물리 netlist 계층을 센 것으로 각 경로가 수학적으로 같은 샘플의 연산을 모두 수행한다는 뜻은 아니다.

## 기준본과 비교 및 해석

기준본 최악 경로는 WNS +0.093ns, 14.888ns(논리 7.851ns·배선 7.037ns), FSM 제어 레지스터→일반 레지스터 입력이다. C01은 최악 경로가 BRAM 주소 입력으로 이동하고 배선 지연이 0.590ns 증가했다. 두 경로의 구간과 endpoint가 다르므로 각 지연 차이를 특정 회로 하나의 기여로 볼 수 없다.

sigmoid 표의 BRAM 전환 및 그로 인한 1클록 조회·스케줄 변경과 타이밍 악화가 함께 관측됐다. BRAM 자체가 언제나 느리거나, 읽기 latency 1클록이 II를 3으로 만든다는 결론은 아니다. C01 LOOP_T II는 2다. 공유된 활성화·곱셈 입력의 선택 경로와 진짜 상태 의존성을 모두 고려해야 한다.

후속 아이디어로 입력을 BRAM 주소 전에 레지스터로 끊거나 공유를 조정하는 방안을 생각할 수 있지만, GRU 재귀 의존성 때문에 II·정확도·자원에 영향을 줄 수 있다. 별도 후보 구현과 C-sim·csynth·P&R이 필요하며 실행 요청을 뜻하지 않는다.
